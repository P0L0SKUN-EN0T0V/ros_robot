Hybrid A*

Алгоритм №9 — A* с учётом физики: руль, скорость, кинематика

Зачем это нужно

Представь, что ты вызвал такси. Навигатор показывает маршрут — набор поворотов по улицам. Теперь представь, что навигатор говорит: «поверни на 90° на месте, потом шаг вбок». Водитель так не сможет — у машины есть руль с ограниченным углом и минимальный радиус разворота. Hybrid A* — это навигатор, который знает, что ты за рулём, а не на своих двоих.

Все алгоритмы до этого (A*, D* Lite, JPS, LPA*) считают, что робот — точка, которая шагает по клеткам. Hybrid A* — первый алгоритм в нашем списке, который учитывает физику робота: угол поворота $\theta$, минимальный радиус $R_{min}$, длину колёсной базы $L$.

Состояние — не $(x, y)$, а $(x, y, \theta)$. Переходы — не шаги по сетке, а реальные дуги, по которым робот может проехать.

Модель велосипеда (bicycle model)

Неважно, четыре колеса у робота или два — кинематику можно упростить до двухколёсной модели. Переднее колесо рулит, заднее катится. Этого достаточно, чтобы описать и TurtleBot, и автомобиль, и погрузчик.

$$\dot{x} = v \cos\theta, \quad \dot{y} = v \sin\theta, \quad \dot{\theta} = \frac{v}{L} \tan\delta$$

Где:

СимволЧто означает
$v$Линейная скорость (вперёд/назад)
$\theta$Текущий угол ориентации робота (heading)
$L$Колёсная база — расстояние между осями
$\delta$Угол поворота руля ($-\delta_{max}$ до $+\delta_{max}$)
$R_{min}$Минимальный радиус поворота = $L / \tan(\delta_{max})$

Дискретизация (один шаг длиной $\Delta s$):

$$x' = x + \Delta s \cdot \cos\theta, \quad y' = y + \Delta s \cdot \sin\theta, \quad \theta' = \theta + \frac{\Delta s}{L} \tan\delta$$

Ключевое ограничение: робот не может двигаться вбок. Если цель сбоку — приходится объезжать дугой. Это и есть неголономность (nonholonomic constraint).

Пространство состояний: 2D → 3D

Обычный A*

Состояние: $(x, y) \in \mathbb{Z}^2$

8 соседей, шаг = 1 клетка

Разворот на месте — бесплатно

Пешеход: куда хочу, туда иду

Hybrid A*

Состояние: $(x, y, \theta) \in \mathbb{R}^2 \times [0, 2\pi)$

3–7 маневров (углы руля)

Минимальный радиус поворота $R_{min}$

Водитель: кручу руль, еду дугами

Сетка нужна только для дискретизации: в каждой ячейке $(i, j, k)$ хранится лучшее непрерывное состояние. $k$ — дискретный угол ($\theta$ делим на $N_\theta$ секторов, обычно 36–72).

Маневры: что умеет робот

На каждом шаге робот проезжает расстояние $\Delta s$ и крутит руль на один из фиксированных углов. Это и есть его «соседи» — только не клетки, а дуги.

МаневрУгол руля $\delta$Что происходит
Прямо$0$Едет прямо на $\Delta s$
Лево макс.$+\delta_{max}$Крутая дуга влево (радиус $R_{min}$)
Право макс.$-\delta_{max}$Крутая дуга вправо (радиус $R_{min}$)
Лево плавно$+\delta_{max}/2$Плавная дуга влево (радиус $2R_{min}$)
Право плавно$-\delta_{max}/2$Плавная дуга вправо (радиус $2R_{min}$)

Обычно 3–5 маневров. Больше → плавнее путь, но дольше поиск.

Как работает

1
Дискретизация пространства. Карту разбиваем на сетку (как OccupancyGrid). Угол $\theta$ — на $N_\theta$ секторов (шаг 5°–10°). Каждая ячейка — тройка $(i, j, k)$.
2
Старт. Кладём $(x_0, y_0, \theta_0)$ в open list с $f = h(\text{start})$.
3
Expand. Берём лучший из open list, применяем все маневры → получаем 3–5 новых состояний.
4
Collision check. Каждая дуга проверяется на столкновение с учётом footprint робота (не точка, а прямоугольник).
5
Deduplicate. Вычисляем ячейку $(i', j', k')$. Если там уже есть состояние с меньшим $g$ — пропускаем.
6
Analytic expansion. Каждые N шагов пробуем Reeds-Shepp / Dubins кривую напрямую к цели. Если проходит — нашли путь!

Analytic expansion — главная оптимизация. Вместо того чтобы ползти дугами до самого финиша, мы периодически пробуем аналитическую кривую напрямую к цели. Вблизи цели это срабатывает и ускоряет финал в десятки раз.

Двойная эвристика

Hybrid A* уникален тем, что использует две разных эвристики одновременно — и берёт максимум. Каждая «знает» то, чего не знает другая:

$h_1$: Кинематика без стен

Длина Dubins/Reeds-Shepp кривой до цели, игнорируя препятствия.

Знает про руль и радиус поворота, но не видит стены.

$h_1 = \text{Dubins}(\text{state}, \text{goal})$

$h_2$: Стены без кинематики

Обычный 2D A*/Dijkstra от позиции до цели, игнорируя угол $\theta$.

Видит стены и обходит их, но не знает про руль.

$h_2 = \text{2D\_Grid}(x, y, \text{goal})$
$$h(s) = \max\big(h_1(s),\; h_2(s)\big)$$

Максимум двух допустимых эвристик — тоже допустимая эвристика, но более точная. Это отсекает больше бесполезных состояний.

Визуальный пример

Одна и та же карта, одни и те же препятствия — но два разных алгоритма рисуют принципиально разные пути:

A* — ступенчатый путь

Резкие повороты на 90°. Робот так не проедет.

Hybrid A* — плавные дуги

Плавная кривая с учётом $R_{min}$. Робот проедет сразу.

Интерактивная анимация

Смотри, как Hybrid A* расширяет дуги шаг за шагом. Серые дуги — отброшенные маневры (коллизия или уже visited). Оранжевые — принятые. Зелёная — финальный путь.

Псевдокод

function HybridAStar(start, goal, grid):
    open ← priority_queue()
    open.push(start, f = h(start))
    visited[discretize(start)] ← start

    while open не пуст:
        cur ← open.pop_min()

        // Analytic expansion: пробуем кривую напрямую к цели
        if iteration % N == 0:
            curve ← ReedsShepp(cur, goal)
            if collision_free(curve):
                return reconstruct(cur) + curve

        // Expand: применяем каждый маневр
        for δ ∈ {-δmax, -δmax/2, 0, +δmax/2, +δmax}:
            next ← simulate(cur, δ, Δs)
            cell ← discretize(next)  // (i, j, kθ)

            if !collision_free(arc(cur, next)): continue
            if cell ∈ visited and visited[cell].g ≤ next.g: continue

            next.g ← cur.g + arc_length
            next.f ← next.g + max(hdubins(next), h2d(next))
            next.parent ← cur
            visited[cell] ← next
            open.push(next)

    return null  // путь не найден

Реализация в C++ (ROS2)

Ключевые компоненты: 3D-состояние, bicycle model, analytic expansion через OMPL.

// hybrid_astar_planner.hpp
#include <nav_msgs/msg/occupancy_grid.hpp>
#include <ompl/base/spaces/ReedsSheppStateSpace.h>
#include <queue>
#include <cmath>

constexpr int N_THETA = 72;            // 5° шаг угла
constexpr double ANGLE_RES = 2*M_PI / N_THETA;
constexpr double L = 0.3;              // колёсная база [м]
constexpr double DS = 0.1;             // шаг [м]
constexpr double DELTA_MAX = 0.5;      // макс. угол руля [рад]
constexpr double R_MIN = L / tan(DELTA_MAX);

struct State3D {
    double x, y, theta;
    double g = 0, f = 0;
    int parent_idx = -1;

    // Дискретизация для visited-массива
    int ix(double res) const { return (int)(x / res); }
    int iy(double res) const { return (int)(y / res); }
    int itheta() const {
        int k = (int)(theta / ANGLE_RES);
        return ((k % N_THETA) + N_THETA) % N_THETA;
    }
};

// Кинематическая модель (bicycle)
State3D simulate(const State3D& s, double delta) {
    State3D n;
    n.x = s.x + DS * cos(s.theta);
    n.y = s.y + DS * sin(s.theta);
    n.theta = s.theta + (DS / L) * tan(delta);
    // Нормализуем угол в [0, 2π)
    n.theta = fmod(n.theta, 2*M_PI);
    if (n.theta < 0) n.theta += 2*M_PI;
    return n;
}

// Analytic expansion: Reeds-Shepp кривая к цели

Какой планировщик выбрать

A* / JPS

Робот omnidirectional (может ехать в любую сторону). Дроны, mecanum-колёса, дифф-привод без ограничений.
Точка на сетке, быстро, оптимально

Nav2: SmacPlanner2D

Hybrid A*

Робот с рулём — автомобиль, Ackermann, вилочный погрузчик. Есть $R_{min}$, нужен сразу проезжаемый путь.
Дуги в 3D, учёт кинематики, ~оптимально

Nav2: SmacPlannerHybrid

Lattice Planner

Сложная кинематика, нужны предрассчитанные маневры (parallel parking, 3-point turn). Индустриальные AGV.
Таблица маневров, дорогой precompute

Nav2: SmacPlannerLattice

Когда использовать

Подходит

  • Ackermann-роботы (автомобили, вилочники) — путь сразу проезжаемый
  • Парковка в тесных пространствах — Reeds-Shepp включает задний ход
  • Outdoor навигация — крупная карта, робот с рулём

Не подходит

  • Omnidirectional роботы — для них обычный A* проще и быстрее
  • Дроны / манипуляторы — им нужен 6-DOF, а не 3-DOF
  • Очень большие карты без analytic expansion — поиск будет медленным

Сложность: Время — $O(N_\theta \cdot V \cdot B \cdot \log(N_\theta V))$, где $V$ = клетки сетки, $B$ = число маневров, $N_\theta$ = секторы угла. Память — $O(N_\theta \cdot V)$ для 3D visited-массива. Analytic expansion — $O(1)$ на попытку (аналитические формулы Dubins/Reeds-Shepp).
