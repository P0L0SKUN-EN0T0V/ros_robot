Theta* — Any-Angle Path Planning

Алгоритм №5 — A*, который умеет ходить не только по клеткам

О чём вообще речь

У A* есть одна раздражающая проблема: путь всегда идёт по рёбрам сетки — горизонтально, вертикально или по диагонали (45°). Робот движется ступеньками, хотя мог бы просто пройти по прямой. Результат: путь длиннее, чем нужно, а робот делает кучу лишних поворотов.

Theta* решает это одним простым вопросом: «А видит ли родитель моего родителя меня напрямую?» Если да — зачем промежуточный узел? Рисуем прямую линию и срезаем угол.

Представь, что ты идёшь по городу строго по тротуарам (A*). Дошёл до перекрёстка, повернул, дошёл до следующего, снова повернул. Но если посмотреть — через площадь можно было пройти напрямую по диагонали, срезав оба поворота. Theta* — это ты, который каждый раз оглядывается назад и спрашивает: «А я вижу тот перекрёсток, откуда пришёл? Может, мне срезать?»
Theta* = A* + проверка прямой видимости (line-of-sight).
Всё остальное — та же сетка, та же эвристика, та же priority queue. Разница — один дополнительный if при обновлении узла.

Проблема A*: путь по ступенькам

Посмотри на сетку 5×5 без препятствий. Нужно пройти от (0,0) до (4,4). A* пойдёт по диагонали — вроде неплохо. Но если цель не на диагонали — например, (0,0) → (4,2) — A* будет «лесенкой»: диагональ-диагональ-горизонталь-диагональ. Путь получается длиннее геометрически оптимального (прямой линии) на 5–15%.

Theta* устраняет эту проблему. Узлы пути могут соединяться любыми прямыми линиями (any-angle), а не только рёбрами сетки. Результат — путь, который выглядит так, как будто его прокладывал человек, а не робот.

Математика

Theta* использует ту же формулу приоритета, что и A*:

$$f(n) = g(n) + h(n)$$

Но $g(n)$ может вычисляться двумя способами — и в этом вся магия:

Путь 1: Через соседа (как в A*)

$$g_1(n) = g(\text{parent}(s)) + \text{dist}(\text{parent}(s),\; n)$$

Здесь $s$ — текущий сосед, через которого мы пришли к $n$. Это стандартный A*-вариант: стоимость до родителя $s$ + расстояние от $s$ до $n$.

Путь 2: Через «дедушку» (line-of-sight)

$$g_2(n) = g(\text{parent}(\text{parent}(s))) + \text{dist}(\text{parent}(\text{parent}(s)),\; n)$$

А тут мы спрашиваем: вижу ли я «дедушку» — родителя моего родителя — напрямую? Если между нами нет препятствий (line-of-sight), то зачем промежуточный узел? Идём напрямую к «дедушке», путь короче.

Правило выбора:
Если line_of_sight(parent(parent(s)), n) = true и $g_2(n) < g_1(n)$:
→ используем Путь 2 (через «дедушку»), parent(n) = parent(parent(s))

Иначе:
→ используем Путь 1 (стандартный A*), parent(n) = s

Проверка прямой видимости (Line-of-Sight)

Ключевая операция Theta*. Проверяем, можно ли провести прямую линию от точки A до точки B, не задев ни одной занятой клетки. Используется алгоритм Брезенхема (тот же, что рисует линии на экране):

$$\text{LineOfSight}(A, B) = \forall\, \text{cell} \in \text{Bresenham}(A, B): \;\text{cell} \neq \text{obstacle}$$

Простым языком: проводим виртуальную линию от A до B, проверяем каждую клетку на пути. Если хоть одна занята — прямой видимости нет.

Как работает: пошагово

Шаги почти идентичны A*. Единственное отличие — шаг 4:

1
Помещаем старт в open list, $g(\text{start}) = 0$.
2
Извлекаем узел с минимальным $f(n)$ из open list.
3
Если это цель — восстанавливаем путь по parent-ссылкам. Готово!
4
КЛЮЧЕВОЙ ШАГ: Для каждого соседа $n$ текущего узла $s$:
a) Проверяем line-of-sight от parent(s) до $n$.
b) Если видимость есть и путь через parent(s) короче → устанавливаем parent(n) = parent(s) и $g(n)$ = путь через parent(s).
c) Если видимости нет → стандартный A*: parent(n) = s, $g(n)$ = путь через s.
d) Обновляем $f(n) = g(n) + h(n)$, добавляем в open list.
5
Возвращаемся к шагу 2.

Псевдокод

Theta_Star(start, goal, grid):
    open_list = priority_queue()
    g[start] = 0
    f[start] = h(start, goal)
    parent[start] = start
    open_list.push(start, f[start])

    while open_list is not empty:
        s = open_list.pop()       // узел с минимальным f

        if s == goal:
            return reconstruct_path(parent, goal)

        for each neighbor n of s:
            if n is obstacle: continue

            // === ОТЛИЧИЕ ОТ A*: проверка line-of-sight ===
            if line_of_sight(parent[s], n):
                // Путь 2: через "дедушку"
                new_g = g[parent[s]] + dist(parent[s], n)
                if new_g < g[n]:
                    g[n] = new_g
                    f[n] = new_g + h(n, goal)
                    parent[n] = parent[s]     // "дедушка"!
                    open_list.push(n, f[n])
            else:
                // Путь 1: стандартный A*
                new_g = g[s] + dist(s, n)
                if new_g < g[n]:
                    g[n] = new_g
                    f[n] = new_g + h(n, goal)
                    parent[n] = s
                    open_list.push(n, f[n])

    return FAILURE


line_of_sight(A, B):     // алгоритм Брезенхема
    dx = abs(B.x - A.x),  dy = abs(B.y - A.y)
    sx = sign(B.x - A.x), sy = sign(B.y - A.y)
    err = dx - dy
    x = A.x, y = A.y

    while (x, y) != (B.x, B.y):
        if grid[x][y] is obstacle: return false
        e2 = 2 * err
        if e2 > -dy: err -= dy; x += sx
        if e2 <  dx: err += dx; y += sy

    return true
Всего одно отличие от A*: блок if line_of_sight(parent[s], n). Если видимость есть — привязываем узел к «дедушке». Если нет — работаем как обычный A*. Вот и вся «магия».

Сложность

МетрикаЗначениеПояснение
Время $O(N^2 \log N)$ Как A*, но каждый шаг дороже из-за line-of-sight проверки (Брезенхем: $O(\sqrt{N})$ в худшем случае)
Память $O(N)$ Такая же, как у A*: open list + closed set + g/f/parent массивы
Полнота Полный Если путь существует — найдёт. Работает на сетке, как A*
Оптимальность Почти оптимален Не гарантирует строгий оптимум (в отличие от A*), но на практике даёт пути, очень близкие к оптимальным
Почему «почти» оптимален? Theta* проверяет line-of-sight только к parent(s), а не ко всем предкам. Теоретически, связь с «прадедушкой» могла бы дать ещё более короткий путь. Но на практике разница мизерная, а проверка всех предков — дорогая.

Плюсы и минусы

Плюсы

  • Пути короче и прямее, чем у A* — на 5–15%
  • Минимальное отличие от A* — легко реализовать, если уже есть A*
  • Меньше поворотов → робот движется плавнее и быстрее
  • Полный алгоритм — всегда находит путь, если он есть
  • Работает на стандартной OccupancyGrid

Минусы

  • Медленнее A* из-за проверок line-of-sight (Брезенхем на каждом шаге)
  • Не строго оптимален (но очень близок к оптимуму)
  • Работает только на 2D сетках (не для многомерных пространств)
  • Line-of-sight check может быть дорогой на больших картах

Интеграция с ROS2 (C++)

Показываю только отличие от A* — функцию line-of-sight и модифицированный цикл обновления соседей:

// Line-of-Sight check (алгоритм Брезенхема)
bool line_of_sight(int x0, int y0, int x1, int y1,
                   const nav_msgs::msg::OccupancyGrid& grid) {
    int dx = std::abs(x1 - x0), dy = std::abs(y1 - y0);
    int sx = (x0 < x1) ? 1 : -1;
    int sy = (y0 < y1) ? 1 : -1;
    int err = dx - dy;

    while (x0 != x1 || y0 != y1) {
        if (grid.data[y0 * grid.info.width + x0] > 50)
            return false;  // препятствие!

        int e2 = 2 * err;
        if (e2 > -dy) { err -= dy; x0 += sx; }
        if (e2 <  dx) { err += dx; y0 += sy; }
    }
    return true;
}

// Внутри основного цикла A* — замена блока обновления соседа:
for (auto [nx, ny] : neighbors(cx, cy)) {
    if (closed[ny][nx] || is_wall(nx, ny)) continue;

    // === THETA*: проверяем line-of-sight к parent(current) ===
    int px = parent_x[cy][cx];  // координаты родителя текущего узла
    int py = parent_y[cy][cx];

    if (line_of_sight(px, py, nx, ny, *map_)) {
        // Путь 2: через "дедушку"
        double new_g = g[py][px] + hypot(nx - px, ny - py);
        if (new_g < g[ny][nx]) {
            g[ny][nx] = new_g;
            f[ny][nx] = new_g + heuristic(nx, ny, gx, gy);
            parent_x[ny][nx] = px;  // привязываем к "дедушке"!
            parent_y[ny][nx] = py;
            open.push({f[ny][nx], nx, ny});
        }
    } else {
        // Путь 1: стандартный A*
        double new_g = g[cy][cx] + hypot(nx - cx, ny - cy);
        if (new_g < g[ny][nx]) {
            g[ny][nx] = new_g;
            f[ny][nx] = new_g + heuristic(nx, ny, gx, gy);
            parent_x[ny][nx] = cx;
            parent_y[ny][nx] = cy;
            open.push({f[ny][nx], nx, ny});
        }
    }
}
Ключевые моменты в коде:
  • line_of_sight() — алгоритм Брезенхема, проверяет отрезок по клеткам. Сложность $O(\max(dx, dy))$
  • parent_x/parent_y — хранят координаты родителя каждого узла. В Theta* родитель может быть не соседом!
  • hypot(nx - px, ny - py) — евклидово расстояние, не Manhattan. В Theta* расстояния считаются по прямой
  • Если line-of-sight удался — узел привязывается к «дедушке», пропуская промежуточный узел

Когда использовать Theta*

Используй Theta*, если:

  • У тебя уже есть A* и нужно улучшить качество путей минимальными усилиями
  • Робот может двигаться под любым углом (не только 0°/45°/90°)
  • Важна плавность движения и минимум поворотов
  • Карта 2D — OccupancyGrid из лидара

НЕ используй Theta*, если:

  • Пространство многомерное (6D+) — используй RRT/RRT*
  • Нужен строго оптимальный путь — используй ANYA или A* с пост-обработкой
  • Карта очень плотная (лабиринт) — line-of-sight почти никогда не срабатывает, overhead впустую
  • Скорость критична и каждая миллисекунда на счету — A* или JPS быстрее
