Шаг 1: Gazebo и RViz

Устанавливаем и запускаем — видим робота своими глазами

Два инструмента — два назначения

В предыдущем шаге мы узнали, что кроме нашей ноды есть «готовые» программы. Две главных:

Gazebo — симулятор мира

Gazebo создаёт виртуальный 3D-мир: комнаты, стены, мебель. В этом мире «живёт» виртуальный робот (TurtleBot3). У робота есть виртуальный лидар, который стреляет лазерными лучами и измеряет расстояния — точно как настоящий.

Gazebo автоматически публикует данные сенсоров в топики /scan и /odom, и исполняет команды движения из /cmd_vel.

RViz — визуализатор данных

RViz ничего не симулирует. Он просто подписывается на топики и рисует то, что видит: карту, путь, позицию робота, лучи лидара. Это как монитор — показывает информацию, но не создаёт её.

Gazebo — это сцена театра (декорации, актёры, физика). RViz — это монитор видеонаблюдения за кулисами. Один создаёт реальность, другой показывает что происходит.

Установка ROS2 Humble

Мы используем ROS2 Humble Hawksbill — стабильную LTS-версию. Работает на Ubuntu 22.04.

Важно: ROS2 официально поддерживает только Ubuntu. Если у тебя Windows — используй WSL2 (Windows Subsystem for Linux) с Ubuntu 22.04. Если macOS — нужна виртуальная машина.

Шаг за шагом

1
Настраиваем источник пакетов
sudo apt update && sudo apt install -y software-properties-common curl
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
2
Устанавливаем ROS2 Humble (полная версия)
sudo apt update && sudo apt install -y ros-humble-desktop

Это ~2 GB. Включает ROS2 + RViz + Gazebo Classic + демо-пакеты.

3
Устанавливаем инструменты сборки
sudo apt install -y python3-colcon-common-extensions python3-rosdep

colcon — утилита для сборки ROS2-проектов (аналог make/cmake, но для ROS2).

4
Активируем ROS2 в терминале
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
source ~/.bashrc

Эта строка подгружает все ROS2-команды при открытии терминала. Без неё команды вроде ros2 не будут работать.

5
Проверяем
ros2 --version

Должно вывести что-то вроде ros2 0.20.x. Если видишь ошибку «command not found» — перезапусти терминал.

Установка TurtleBot3

TurtleBot3 — маленький учебный робот. Мы используем его виртуальную модель в Gazebo.

sudo apt install -y ros-humble-turtlebot3-gazebo ros-humble-turtlebot3-description ros-humble-turtlebot3-teleop

Также нужно указать модель робота. Есть три варианта: burger (простой), waffle (с камерой), waffle_pi. Для нашего проекта подойдёт burger — у него есть лидар, и этого достаточно:

echo "export TURTLEBOT3_MODEL=burger" >> ~/.bashrc
source ~/.bashrc

Запускаем Gazebo

Открой терминал и запусти:

ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py

Что произойдёт:

  1. Откроется окно Gazebo с 3D-миром — стены, цилиндры, пол.
  2. В центре (или рядом) появится маленький робот — TurtleBot3.
  3. В терминале побегут логи — это нормально.

Первый запуск — медленный. Gazebo скачивает модели (текстуры, меши). Может занять 1-3 минуты. Не закрывай — дождись, пока появится окно.

Checkpoint: Видишь окно Gazebo с роботом и стенами? Отлично — симулятор работает. Если окно не появилось через 3 минуты — проверь, что TURTLEBOT3_MODEL задан: echo $TURTLEBOT3_MODEL.

Проверяем: что публикует Gazebo

Не закрывая Gazebo, открой второй терминал и выполни:

ros2 topic list

Увидишь список всех активных топиков. Среди них будут:

/clock
/cmd_vel
/imu
/joint_states
/odom
/parameter_events
/rosout
/scan
/tf
/tf_static

Нас интересуют:

  • /scan — данные лидара
  • /odom — позиция робота
  • /cmd_vel — сюда мы будем писать команды

Заглянем в данные лидара

ros2 topic echo /scan --once

Команда выведет одно сообщение типа LaserScan. Увидишь массив ranges — это расстояния в метрах от лидара до ближайших объектов для каждого угла. Числа ~0.1-3.5 — стены рядом, inf — ничего не обнаружено.

Заглянем в одометрию

ros2 topic echo /odom --once

Увидишь pose.pose.position.x, ...y — текущие координаты робота в метрах. И orientation — кватернион (куда робот повёрнут).

Покатаем робота вручную

Чтобы убедиться, что робот «живой» и реагирует на команды, запустим телеуправление с клавиатуры:

ros2 run turtlebot3_teleop teleop_keyboard

В терминале появятся инструкции:

  • w — вперёд
  • x — назад
  • a — повернуть налево
  • d — повернуть направо
  • s — стоп

Попробуй покатать. В окне Gazebo увидишь, как робот двигается. Под капотом teleop_keyboard просто публикует сообщения Twist в топик /cmd_vel — точно так же, как будет делать наша нода.

Checkpoint: Робот двигается при нажатии клавиш? Значит связка «топик → Gazebo → движение» работает. Наша нода будет делать то же самое — только автоматически.

Запускаем RViz

Не закрывая ни Gazebo, ни телеуправление, открой третий терминал:

ros2 run rviz2 rviz2

Откроется окно RViz — пока пустое, с чёрным фоном и сеткой. Нужно добавить отображения:

1
Fixed Frame — в левой панели вверху (Global Options) измени Fixed Frame на odom.
2
Лидар — внизу нажми Add → вкладка By topic → найди /scan → выбери LaserScan → OK. Появятся красные точки — это то, что видит лидар.
3
Робот — нажми Add → вкладка By display type → RobotModel → OK. Появится модель робота.
4
Одометрия — Add → By topic → /odom → Odometry → OK. Появится стрелка — направление движения.

Теперь покатай робота в телеуправлении — увидишь, как в RViz обновляются точки лидара и стрелка одометрии.

Сохрани конфигурацию RViz: File → Save Config As → my_config.rviz. Иначе при следующем запуске придётся добавлять всё заново.

Как ставить цель в RViz

В нашем проекте мы будем задавать цель через RViz. Вот как:

1
В верхней панели RViz найди кнопку «2D Goal Pose» (иконка зелёной стрелки).
2
Кликни на карту и потяни — стрелка покажет направление. Отпусти.
3
RViz опубликует сообщение PoseStamped в топик /goal_pose.

Сейчас ничего не произойдёт — потому что никто не подписан на /goal_pose. Но когда мы напишем нашу ноду, она будет слушать этот топик и строить путь к цели.

Создаём ROS2-проект

ROS2 организует код в пакеты (packages). Пакет — это папка с кодом, файлами сборки и описанием. Создадим наш:

1
Создаём workspace (рабочую область)
mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src
2
Создаём пакет
ros2 pkg create --build-type ament_cmake global_planner --dependencies rclcpp sensor_msgs nav_msgs geometry_msgs tf2 tf2_ros

Что тут написано:

  • ament_cmake — система сборки (для C++)
  • global_planner — имя нашего пакета
  • --dependencies — библиотеки, которые нам понадобятся
3
Проверяем структуру 
~/ros2_ws/
└── src/
    └── global_planner/
        ├── CMakeLists.txt      ← настройки сборки
        ├── package.xml         ← описание пакета и зависимости
        ├── include/             ← заголовочные файлы (.hpp)
        │   └── global_planner/
        └── src/                 ← исходный код (.cpp)
            └── (пока пусто — тут будет наш код)
4
Собираем (пока пустой пакет)
cd ~/ros2_ws && colcon build --packages-select global_planner

Если видишь Finished <<< global_planner — всё собралось.

source install/setup.bash

Эта команда подгружает наш пакет в текущий терминал.

Checkpoint: Пакет собрался без ошибок? Отлично. Теперь у нас есть каркас проекта — осталось написать код ноды.
