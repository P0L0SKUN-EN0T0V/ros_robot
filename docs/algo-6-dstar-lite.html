D* Lite — Dynamic A*

Алгоритм №6 — LPA*, вывернутый наизнанку для движущегося робота

О чём вообще речь

Все алгоритмы до этого предполагали, что карта статична — нарисовали стены, запустили поиск, нашли путь, поехали. Но реальный мир так не работает. Робот едет по коридору и вдруг — дверь закрылась. Или человек встал на пути.

Что делает A*? Весь путь — в мусорку, пересчитай заново. На карте 1000×1000 полный пересчёт — сотни миллисекунд. Робот стоит и ждёт.

GPS-навигатор в машине. Ты едешь по маршруту, и вдруг дорога перекрыта. Навигатор не пересчитывает маршрут с нуля от дома — он перестраивает кусок пути от текущей позиции. D* Lite работает так же.

А чем он отличается от LPA*?

LPA* (алгоритм №8) тоже пересчитывает инкрементально, но у него старт фиксирован. Робот стоит на месте и наблюдает, как меняется карта. D* Lite — для ситуации, когда робот двигается. Старт каждый раз — текущая позиция робота.

Если LPA* — это наблюдатель за экраном мониторинга, то D* Lite — это водитель, который едет и реагирует на изменения дороги.

Почему «задом наперёд»?

Это самый контринтуитивный момент. A* ищет от робота к цели. D* Lite — от цели к роботу. Зачем?

Робот движется вперёд, и новые препятствия появляются рядом с ним (он видит их сенсорами). Если дерево поиска растёт от цели — изменения затрагивают только «листья» (рядом с роботом), а не «корень» (цель). Обновить листья дешёво. Обновить корень — дорого.

Аналогия: представь дерево. Если ветер обломит пару веточек на краю кроны — дерево в целом стоит. Но если подрубить ствол — упадёт всё. D* Lite ставит «корень» на цель, а «веточки» — у робота. Новые препятствия = обломанные веточки, не подрубленный ствол.

Формулы

Движение

8 направлений: кардинальные (стоимость 1), диагональные (стоимость $\sqrt{2} \approx 1.4$).

g и rhs (от цели!)

Как в LPA*, но в обратном направлении. $g(s)$ = расстояние от $s$ до цели, а не от старта.

$rhs(s) = \begin{cases} 0 & \text{если } s = s_{goal} \\ \min_{s' \in succ(s)} \big(g(s') + c(s, s')\big) & \text{иначе} \end{cases}$

$g = rhs$ → consistent. $g \neq rhs$ → inconsistent → нужен пересчёт. Всё как в LPA*.

Ключ приоритета

$key(s) = \big[\min(g(s), rhs(s)) + h(s_{robot}, s) + k_m,\;\; \min(g(s), rhs(s))\big]$

Отличие от LPA*: эвристика считается от текущей позиции робота, а не от фиксированного старта. $k_m$ — поправка, которая накапливается при каждом перемещении робота (чтобы не пересчитывать ключи всех узлов).

Эвристика (octile)

$h(a, b) = \max(\Delta x, \Delta y) + (\sqrt{2} - 1) \cdot \min(\Delta x, \Delta y)$

Анимация: как работает D* Lite

Фаза 1: поиск от G к S. Фаза 2: робот шагает на (1,1), видит стену на (2,3), D* Lite чинит путь. В каждой клетке — g и rhs.

Шаг 1 / 8

Псевдокод

// Инициализация
for all s: g(s) = rhs(s) = ∞
rhs(goal) = 0
U.Insert(goal, CalcKey(goal))
k_m = 0; s_robot = s_start

// CalcKey(s)
return [min(g(s), rhs(s)) + h(s_robot, s) + k_m,
        min(g(s), rhs(s))]

// h — octile distance
h(a,b) = max(|dx|,|dy|) + (√2-1)·min(|dx|,|dy|)

// ComputeShortestPath()
while U.TopKey() < CalcKey(s_robot) OR
      rhs(s_robot) ≠ g(s_robot):
    u = U.Pop()
    if g(u) > rhs(u):             // overconsistent
        g(u) = rhs(u)
        for all s ∈ neighbors(u):
            UpdateVertex(s)
    else:                          // underconsistent
        g(u) = ∞
        UpdateVertex(u)
        for all s ∈ neighbors(u):
            UpdateVertex(s)

// Главный цикл
ComputeShortestPath()          // первый поиск
while s_robot ≠ goal:
    s_robot = argmin_{s'∈neighbors} g(s')+c(s_robot,s')
    // робот переместился
    if обнаружены изменения карты:
        k_m += h(s_old, s_robot)
        for each changed cell:
            UpdateVertex(affected neighbors)
        ComputeShortestPath()  // инкрементальный!

Ключевое отличие от LPA*: $k_m$ накапливается при каждом перемещении робота. Это позволяет не пересчитывать ключи всех узлов в очереди — вместо этого поправка добавляется в формулу ключа.

Реализация в C++ (ROS2)

#include <queue>
#include <unordered_map>
#include <cmath>

struct Cell {
    int x, y;
    bool operator==(const Cell& o) const { return x==o.x && y==o.y; }
};
struct CellHash {
    size_t operator()(const Cell& c) const { return std::hash<int>()(c.x*10007+c.y); }
};
using Key = std::pair<double,double>;

class DStarLite {
    int W, H;
    std::vector<std::vector<bool>> grid;
    Cell goal, robot;
    double km = 0;
    std::unordered_map<Cell,double,CellHash> g_val, rhs_val;

    static constexpr double INF = 1e18;
    static constexpr double SQRT2 = 1.41421356;

    using PQE = std::pair<Key,Cell>;
    std::vector<PQE> U;

    // Octile distance
    double h(Cell a, Cell b) {
        int dx=std::abs(a.x-b.x), dy=std::abs(a.y-b.y);
        return std::max(dx,dy)+(SQRT2-1)*std::min(dx,dy);
    }
    double g(Cell s){auto it=g_val.find(s);return it!=g_val.end()?it->second:INF;}
    double rhs(Cell s){auto it=rhs_val.find(s);return it!=rhs_val.end()?it->second:INF;}

    Key calcKey(Cell s){
        double m=std::min(g(s),rhs(s));
        return {m+h(robot,s)+km, m};
    }

    // 8 направлений
    std::vector<std::pair<Cell,double>> neighbors(Cell s){
        std::vector<std::pair<Cell,double>> nb;
        int dx[]={1,-1,0,0,1,1,-1,-1};
        int dy[]={0,0,1,-1,1,-1,1,-1};
        for(int i=0;i<8;i++){
            Cell n={s.x+dx[i],s.y+dy[i]};
            if(n.x>=0&&n.x<W&&n.y>=0&&n.y<H&&!grid[n.y][n.x]){
                double c=(dx[i]!=0&&dy[i]!=0)?SQRT2:1.0;
                nb.push_back({n,c});
            }
        }
        return nb;
    }

    void uRemove(Cell s){
        U.erase(std::remove_if(U.begin(),U.end(),
            [&](auto&e){return e.second==s;}),U.end());
        std::make_heap(U.begin(),U.end(),std::greater<>());
    }
    void uInsert(Cell s,Key k){U.push_back({k,s});std::push_heap(U.begin(),U.end(),std::greater<>());}

public:
    void initialize(int w,int h_,Cell start,Cell g_){
        W=w;H=h_;robot=start;goal=g_;km=0;
        grid.assign(H,std::vector<bool>(W,false));
        rhs_val[goal]=0;
        uInsert(goal,calcKey(goal));
    }

    void updateVertex(Cell u){
        if(!(u==goal)){
            double mn=INF;
            for(auto&[nb,c]:neighbors(u))
                mn=std::min(mn,g(nb)+c);
            rhs_val[u]=mn;
        }
        uRemove(u);
        if(g(u)!=rhs(u)) uInsert(u,calcKey(u));
    }

    void computeShortestPath(){
        while(!U.empty()&&
              (U.front().first<calcKey(robot)||rhs(robot)!=g(robot))){
            std::pop_heap(U.begin(),U.end(),std::greater<>());
            auto[key,u]=U.back();U.pop_back();
            if(g(u)>rhs(u)){
                g_val[u]=rhs(u);
                for(auto&[s,c]:neighbors(u)) updateVertex(s);
            }else{
                g_val[u]=INF;
                updateVertex(u);
                for(auto&[s,c]:neighbors(u)) updateVertex(s);
            }
        }
    }

    // Робот делает шаг
    Cell moveRobot(){
        Cell best=robot;double bestC=INF;
        for(auto&[nb,c]:neighbors(robot)){
            if(g(nb)+c<bestC){bestC=g(nb)+c;best=nb;}
        }
        km+=h(robot,best);
        robot=best;
        return robot;
    }

    // При обнаружении новой стены
    void setWall(int x,int y){
        grid[y][x]=true;
        Cell w={x,y};
        for(auto&[nb,c]:neighbors(w))
            updateVertex(nb);
        computeShortestPath();
    }
};

Сложность

Первый поиск

$O(V \log V)$ — как A*. Выигрыша нет.

Пересчёт после изменения

$O(k \log k)$, где $k$ — inconsistent клетки. При локальном изменении (1–5 стен) $k$ обычно 2–10. На порядки быстрее полного A*.

Когда использовать

Карта не меняется? → Бери A*. Проще, быстрее, меньше памяти.

Карта меняется, робот стоит? → Бери LPA*. Тот же принцип, но проще (без $k_m$).

Карта меняется, робот едет? → Бери D* Lite. Стандарт в ROS2 nav2. Пересчёт за 1–5 мс вместо 50–500 мс у полного A*. Идеален для SLAM, людей, дверей, подвижных объектов.

Подходит

  • Робот движется и обнаруживает препятствия сенсорами
  • SLAM обновляет карту несколько раз в секунду
  • Среда с людьми, дверями, подвижными объектами
  • Нужна гарантия оптимальности после каждого изменения

Не подходит

  • Карта статична → A* проще
  • Нужен any-angle путь → добавь Theta* поверх
  • Многомерное пространство → RRT/RRT*
  • Карта меняется глобально (50%+) → A* с нуля дешевле
