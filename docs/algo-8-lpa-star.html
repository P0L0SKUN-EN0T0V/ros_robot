LPA* — Lifelong Planning A*

Алгоритм №8 — A*, который запоминает предыдущий поиск и не начинает с нуля

О чём вообще речь

Проблема A*

Представь: робот едет по складу и нашёл оптимальный маршрут с помощью A*. Через 10 секунд кто-то поставил коробку на пути. Что делает A*? Выкидывает всю работу и считает заново. Все 200 раскрытых узлов — в мусорку. Даже если коробка заблокировала только одну клетку из двадцати на маршруте.

Это как если бы ты написал диплом на 50 страниц, а научрук сказал «перепиши один абзац на странице 30» — и ты начал заново с титульного листа.

Идея LPA*

LPA* запоминает все результаты первого поиска. Когда карта меняется, он смотрит: «Какие конкретно клетки затронуты?» — и пересчитывает только их. Всё остальное остаётся как было.

Если на карте 1000 клеток и изменилась одна стена — A* пересчитает сотни узлов. LPA* пересчитает 5–10. Разница в скорости — на порядки.

Ты — бухгалтер с Excel-таблицей на 1000 строк. Изменился один входной параметр. Ты не пересчитываешь всю таблицу — Excel сам обновляет только те ячейки, которые зависят от изменённой. LPA* работает так же: у каждой клетки есть «формула», и при изменении пересчитываются только зависимые.

Почему два числа, а не одно?

У обычного A* каждая клетка хранит одно число — g (стоимость пути от старта). У LPA* — два:

  • $g(s)$ — «старое» значение. Что мы посчитали на предыдущем проходе.
  • $rhs(s)$ — «актуальное» значение. Что должно быть сейчас, исходя из текущих соседей.

Когда $g = rhs$ — клетка consistent (согласована). Всё ок, ничего пересчитывать не надо. Когда $g \neq rhs$ — клетка inconsistent (рассогласована). Что-то изменилось, и эту клетку нужно обработать.

Вот и вся магия. Вместо «пересчитай всё» — LPA* говорит: «Найди клетки, где $g \neq rhs$, и исправь только их». Это может быть 3 клетки из 1000.

Ключевые понятия

$g(s)$ — старая оценка

Стоимость пути от S до s, посчитанная на предыдущем проходе. Это «кэш» — то, что мы уже знаем. Обновляется только когда мы раскрываем узел.

$rhs(s)$ — актуальная оценка

Что должно быть по текущей карте. Считается как минимум из $g(s') + cost(s', s)$ по всем соседям $s'$. Обновляется мгновенно при любом изменении.

Overconsistent vs Underconsistent

Если $g(s) > rhs(s)$ — клетка overconsistent. Мы нашли путь лучше, чем раньше. Решение: установить $g(s) = rhs(s)$ (принять улучшение).

Если $g(s) < rhs(s)$ — клетка underconsistent. Путь стал хуже (например, появилась стена). Решение: установить $g(s) = \infty$ (сбросить и пересчитать).

Формулы

Как считать rhs

$rhs(s) = \begin{cases} 0 & \text{если } s = s_{start} \\ \min_{s' \in pred(s)} \big(g(s') + c(s', s)\big) & \text{иначе} \end{cases}$

Проще говоря: rhs старта = 0 (оттуда мы начинаем), а для всех остальных клеток — смотрим на соседей, берём того, через кого дешевле всего добраться.

Ключ приоритета

$key(s) = \big[\min(g(s), rhs(s)) + h(s, s_{goal}),\;\; \min(g(s), rhs(s))\big]$

Два числа — сначала сравниваем первое (аналог $f$ из A*), при равенстве — второе. Чем меньше key — тем раньше обработаем клетку.

UpdateVertex(s)

Вызывается, когда что-то изменилось вокруг клетки $s$:

  1. Если $s \neq s_{start}$: пересчитай $rhs(s)$ по текущим соседям
  2. Убери $s$ из очереди (если была)
  3. Если $g(s) \neq rhs(s)$: добавь $s$ обратно в очередь с новым key

Если после пересчёта $g = rhs$ — клетка стала consistent и в очередь не попадает. Если нет — попадает, и мы её обработаем.

Визуальный пример

Карта 5×5, 4 направления (вверх/вниз/влево/вправо), стоимость шага = 1. S(0,0) — старт, G(4,4) — цель, стены: (2,1) и (2,2).

Фаза 2: появилась стена на (1,3)

Робот едет по маршруту и вдруг обнаруживает: клетка (1,3) заблокирована! Что делает LPA*?

Шаг 1. Помечаем (1,3) как стену. Все соседи, которые использовали (1,3) как часть пути, получают обновление rhs.

Шаг 2. Клетки (2,3) и (1,4) пересчитывают rhs — старый путь через (1,3) больше не доступен. Их rhs меняется → они стали inconsistent.

Шаг 3. LPA* раскрывает только эти 2–4 клетки вместо ~20 у полного A*. Находит обходной путь.

Анимация: как работает LPA*

Два этапа: сначала первый поиск (Фаза 1), потом появляется новая стена и LPA* чинит путь (Фаза 2). Оранжевые — клетки, которые алгоритм обрабатывает прямо сейчас.

Шаг 1 / 10

Псевдокод

// Инициализация
for all s ∈ S:
    g(s) = ∞; rhs(s) = ∞
rhs(s_start) = 0
U.Insert(s_start, CalcKey(s_start))

// CalcKey(s)
return [min(g(s), rhs(s)) + h(s, s_goal),
        min(g(s), rhs(s))]

// UpdateVertex(u)
if u ≠ s_start:
    rhs(u) = min over all predecessors s':
              g(s') + c(s', u)
if u ∈ U: U.Remove(u)
if g(u) ≠ rhs(u): U.Insert(u, CalcKey(u))

// ComputeShortestPath()
while U.TopKey() < CalcKey(s_goal) OR
      rhs(s_goal) ≠ g(s_goal):
    u = U.Pop()
    if g(u) > rhs(u):           // overconsistent
        g(u) = rhs(u)
        for all s ∈ successors(u):
            UpdateVertex(s)
    else:                        // underconsistent
        g(u) = ∞
        UpdateVertex(u)
        for all s ∈ successors(u):
            UpdateVertex(s)

// При изменении карты
for each changed edge (u, v):
    update c(u, v)
    UpdateVertex(v)
ComputeShortestPath()

Ключевой момент: после изменения карты мы не сбрасываем g-значения и не начинаем поиск заново. Мы только обновляем rhs у затронутых клеток и вызываем ComputeShortestPath() — он подхватит inconsistent узлы из очереди и исправит только то, что нужно.

Реализация в C++ (ROS2)

#include <queue>
#include <unordered_map>
#include <vector>
#include <cmath>
#include <algorithm>

// Клетка на сетке
struct Cell {
    int x, y;
    bool operator==(const Cell& o) const { return x==o.x && y==o.y; }
};
struct CellHash {
    size_t operator()(const Cell& c) const { return std::hash<int>()(c.x*10007 + c.y); }
};
using Key = std::pair<double,double>;

class LPAStar {
    int W, H;
    std::vector<std::vector<bool>> grid; // true = blocked
    Cell start, goal;
    std::unordered_map<Cell, double, CellHash> g_val, rhs_val;

    // Priority queue: (key, cell)
    using PQEntry = std::pair<Key, Cell>;
    std::vector<PQEntry> U; // min-heap

    double INF = 1e18;

    double h(Cell s) {
        return std::abs(s.x - goal.x) + std::abs(s.y - goal.y);
    }

    double g(Cell s) { auto it = g_val.find(s); return it != g_val.end() ? it->second : INF; }
    double rhs(Cell s) { auto it = rhs_val.find(s); return it != rhs_val.end() ? it->second : INF; }

    Key calcKey(Cell s) {
        double m = std::min(g(s), rhs(s));
        return {m + h(s), m};
    }

    std::vector<Cell> neighbors(Cell s) {
        std::vector<Cell> nb;
        int dx[] = {1,-1,0,0}, dy[] = {0,0,1,-1};
        for (int i = 0; i < 4; i++) {
            Cell n = {s.x+dx[i], s.y+dy[i]};
            if (n.x>=0 && n.x<W && n.y>=0 && n.y<H && !grid[n.y][n.x])
                nb.push_back(n);
        }
        return nb;
    }

    void uRemove(Cell s) {
        U.erase(std::remove_if(U.begin(), U.end(),
            [&](auto& e){ return e.second == s; }), U.end());
        std::make_heap(U.begin(), U.end(), std::greater<>());
    }

    void uInsert(Cell s, Key k) {
        U.push_back({k, s});
        std::push_heap(U.begin(), U.end(), std::greater<>());
    }

public:
    void initialize(int w, int h_, Cell s, Cell g_) {
        W=w; H=h_; start=s; goal=g_;
        grid.assign(H, std::vector<bool>(W, false));
        rhs_val[start] = 0;
        uInsert(start, calcKey(start));
    }

    void updateVertex(Cell u) {
        if (!(u == start)) {
            double mn = INF;
            for (auto& nb : neighbors(u))
                mn = std::min(mn, g(nb) + 1.0);
            rhs_val[u] = mn;
        }
        uRemove(u);
        if (g(u) != rhs(u))
            uInsert(u, calcKey(u));
    }

    void computeShortestPath() {
        while (!U.empty() &&
               (U.front().first < calcKey(goal) || rhs(goal) != g(goal))) {
            std::pop_heap(U.begin(), U.end(), std::greater<>());
            auto [key, u] = U.back(); U.pop_back();

            if (g(u) > rhs(u)) {
                g_val[u] = rhs(u);              // overconsistent
                for (auto& s : neighbors(u))
                    updateVertex(s);
            } else {
                g_val[u] = INF;                  // underconsistent
                updateVertex(u);
                for (auto& s : neighbors(u))
                    updateVertex(s);
            }
        }
    }

    // Вызови при изменении карты
    void setWall(int x, int y) {
        grid[y][x] = true;
        Cell w = {x, y};
        for (auto& nb : neighbors(w))
            updateVertex(nb);
        computeShortestPath();
    }
};

Сложность

Первый поиск

$O(V \log V)$ — как A*. Ни лучше, ни хуже. Первый раз LPA* не даёт преимущества.

Инкрементальный пересчёт

$O(k \log k)$, где $k$ — количество inconsistent клеток. При локальном изменении $k \ll V$, и это на порядки быстрее полного A*.

Когда использовать

Подходит

  • Карта меняется часто, но локально (1–5 клеток за раз)
  • Старт и цель фиксированы — робот не двигается между пересчётами
  • Нужна гарантия оптимальности после каждого изменения
  • Система мониторинга: «покажи оптимальный путь в реальном времени»

Не подходит

  • Карта меняется глобально (50%+ клеток) — дешевле пересчитать A* с нуля
  • Робот двигается → используй D* Lite
  • Карта не меняется вообще → обычный A* проще и быстрее
  • Нужно планировать для разных стартов — LPA* привязан к одному

Продвинутые варианты

D* Lite

Тот же принцип (g/rhs, inconsistency), но ищет от цели к старту. Когда робот двигается и обнаруживает новое препятствие — D* Lite пересчитывает только от текущей позиции. По сути, LPA* для движущегося робота.

MPGAA* (Multi-Path GAA*)

Гибрид A* и LPA*: использует несколько путей одновременно и переключается между ними при изменениях. Быстрее чистого LPA* на картах с частыми, но предсказуемыми изменениями.
