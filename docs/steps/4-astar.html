Шаг 4: Ищем путь — A*

Вторая ключевая функция: planAStar

Напоминание: что уже есть

К этому моменту у нас есть:

  • Карта map_data_ — обновляется в реальном времени через updateMapWithLaser.
  • Позиция робота — robot_x_, robot_y_ из одометрии.
  • Цель — goal_x_, goal_y_ из /goal_pose (клик в RViz).

Задача: найти путь от робота до цели по частично известной карте. Это делает A*.

Подробный разбор A* с анимациями — на странице алгоритма. Здесь — только то, что нужно для кода проекта.

A* за 30 секунд

f(n) = g(n) + h(n)
БукваЧто значитПример
g(n)Стоимость пути от старта до клетки nПрошли 5 клеток по прямой + 2 по диагонали
h(n)Оценка расстояния от n до цели (эвристика)Евклидово расстояние «по воздуху»
f(n)Общая оценка «перспективности» клеткиЧем меньше f — тем перспективнее
Ты в лабиринте. На каждом перекрёстке выбираешь: куда идти? A* говорит: «Иди туда, где сумма пройденного пути и расстояния до выхода (по прямой) — наименьшая». Это не жадный выбор (тот бы всегда шёл к цели и упирался в стены) — A* учитывает и уже пройденное расстояние.

Алгоритм по шагам

1
Кладём стартовую клетку в open list (очередь с приоритетами).
2
Берём клетку с наименьшим f из open list.
3
Если это цель — готово, восстанавливаем путь.
4
Иначе — смотрим всех соседей (8 направлений). Для каждого свободного соседа считаем g и f. Если путь через текущую клетку лучше — обновляем.
5
Повторяем шаги 2-4 пока не найдём цель или open list не опустеет (путь невозможен).

Код: planAStar

Полная реализация A* для нашей карты. Это вторая ключевая функция:

// Структура для хранения информации о клетке
struct Cell {
    int x, y;
    double g, f;
    int parent_x, parent_y;
};

// Эвристика — евклидово расстояние
double heuristic(int x1, int y1, int x2, int y2) {
    double dx = x1 - x2;
    double dy = y1 - y2;
    return std::sqrt(dx * dx + dy * dy);
}

// 8 направлений: вверх, вниз, влево, вправо + 4 диагонали
const int DX[] = {-1, -1, -1,  0, 0,  1, 1, 1};
const int DY[] = {-1,  0,  1, -1, 1, -1, 0, 1};

// Возвращает путь как вектор пар (x, y) в координатах сетки
std::vector<std::pair<int,int>> planAStar(int sx, int sy, int gx, int gy) {
    // Проверяем, что старт и цель валидны
    if (!isFree(sx, sy) || !isFree(gx, gy)) return {};

    // g-значения для каждой клетки (изначально бесконечность)
    std::vector<std::vector<double>> g_val(MAP_SIZE,
        std::vector<double>(MAP_SIZE, std::numeric_limits<double>::infinity()));

    // Карта родителей для восстановления пути
    std::vector<std::vector<std::pair<int,int>>> parent(MAP_SIZE,
        std::vector<std::pair<int,int>>(MAP_SIZE, {-1, -1}));

    // Closed set — уже обработанные клетки
    std::vector<std::vector<bool>> closed(MAP_SIZE,
        std::vector<bool>(MAP_SIZE, false));

    // Open list — очередь с приоритетом (min-heap по f)
    // {f, x, y}
    using PQItem = std::tuple<double, int, int>;
    std::priority_queue<PQItem, std::vector<PQItem>, std::greater<PQItem>> open;

    g_val[sy][sx] = 0.0;
    double f0 = heuristic(sx, sy, gx, gy);
    open.push({f0, sx, sy});

    while (!open.empty()) {
        auto [f, cx, cy] = open.top();
        open.pop();

        // Уже обработана?
        if (closed[cy][cx]) continue;
        closed[cy][cx] = true;

        // Нашли цель!
        if (cx == gx && cy == gy) {
            // Восстанавливаем путь от цели к старту
            std::vector<std::pair<int,int>> path;
            int px = gx, py = gy;
            while (px != -1 && py != -1) {
                path.push_back({px, py});
                auto [ppx, ppy] = parent[py][px];
                px = ppx; py = ppy;
            }
            std::reverse(path.begin(), path.end());
            return path;
        }

        // Проверяем 8 соседей
        for (int d = 0; d < 8; d++) {
            int nx = cx + DX[d];
            int ny = cy + DY[d];

            if (!isFree(nx, ny) || closed[ny][nx]) continue;

            // Стоимость шага: 1.0 по прямой, 1.414 по диагонали
            double step_cost = (DX[d] != 0 && DY[d] != 0) ? 1.414 : 1.0;
            double new_g = g_val[cy][cx] + step_cost;

            if (new_g < g_val[ny][nx]) {
                g_val[ny][nx] = new_g;
                double new_f = new_g + heuristic(nx, ny, gx, gy);
                parent[ny][nx] = {cx, cy};
                open.push({new_f, nx, ny});
            }
        }
    }

    // Путь не найден
    return {};
}

Когда вызывать planAStar

A* нужно запускать в двух случаях:

1
Когда получена новая цель — пользователь кликнул в RViz. Нода получила /goal_pose.
2
Периодически (перепланирование) — потому что карта обновляется. Робот может обнаружить новую стену на пути и нужен новый маршрут.
// Callback цели
void goalCallback(const geometry_msgs::msg::PoseStamped::SharedPtr msg) {
    goal_x_ = msg->pose.position.x;
    goal_y_ = msg->pose.position.y;
    has_goal_ = true;

    replan();  // Сразу ищем путь
}

// Перепланирование — вызывается по таймеру (например, каждые 0.5 сек)
void replan() {
    if (!has_goal_) return;

    // Переводим координаты робота и цели из метров в клетки
    int sx = worldToGrid(robot_x_, ORIGIN_X);
    int sy = worldToGrid(robot_y_, ORIGIN_Y);
    int gx = worldToGrid(goal_x_, ORIGIN_X);
    int gy = worldToGrid(goal_y_, ORIGIN_Y);

    current_path_ = planAStar(sx, sy, gx, gy);

    if (current_path_.empty()) {
        RCLCPP_WARN(this->get_logger(), "A* не нашёл путь!");
    } else {
        publishPath();  // Отправляем в /global_plan для RViz
    }
}

Публикация пути в /global_plan

void publishPath() {
    auto path_msg = nav_msgs::msg::Path();
    path_msg.header.stamp = this->get_clock()->now();
    path_msg.header.frame_id = "odom";

    for (auto& [gx, gy] : current_path_) {
        geometry_msgs::msg::PoseStamped pose;
        pose.header = path_msg.header;
        // Обратное преобразование: клетки → метры
        pose.pose.position.x = ORIGIN_X + gx * RESOLUTION + RESOLUTION / 2;
        pose.pose.position.y = ORIGIN_Y + gy * RESOLUTION + RESOLUTION / 2;
        path_msg.poses.push_back(pose);
    }

    path_pub_->publish(path_msg);
}

В RViz добавь отображение: Add → By topic → /global_plan → Path. Увидишь зелёную линию от робота до цели.

Особенности A* на частичной карте

Путь может идти через «туман». Помнишь из прошлого шага? isFree считает неизвестные клетки проходимыми. Поэтому A* спокойно прокладывает путь через них. Когда робот доедет ближе и лидар увидит стену — карта обновится, и replan() построит новый путь.

Это и есть суть проекта: робот едет → видит больше → карта обновляется → путь перестраивается. Цикл «scan → map → plan → drive → scan → ...» крутится постоянно.

Итоги шага

  • A* ищет кратчайший путь на сетке, используя f = g + h.
  • planAStar — принимает координаты старта и цели (в клетках), возвращает путь.
  • Перепланирование — запускается периодически, потому что карта обновляется.
  • Путь через туман — нормальное поведение. Робот исследует мир.

Путь найден — но робот стоит на месте. В следующем шаге научим его ехать по пути с помощью Pure Pursuit.
