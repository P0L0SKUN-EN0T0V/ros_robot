ROS2 Navigation Project

Обзор проекта: что делаем, как устроено, по каким критериям оценивают

Что делаем

В одном предложении: пишем C++ ноду для ROS2, которая управляет виртуальным роботом в симуляторе Gazebo — робот сам строит карту, ищет путь и едет к цели, объезжая препятствия.

У робота есть лидар (видит стены) и одометрия (знает где находится). Мы пишем «мозг» — одну программу с тремя ключевыми функциями:

  1. 1updateMapWithLaser — строит карту из данных лидара
  2. 2planAStar — ищет путь на частичной карте
  3. 3purePursuitControl — едет по найденному пути

Подробный разбор каждой функции — в пошаговом гайде (7 шагов от нуля до рабочего проекта).

Архитектура

В системе три программы. Две готовые, одну пишем мы:

Gazebo готовое
Симулятор мира + робот
Публикует: /scan, /odom
Принимает: /cmd_vel
↔
Наша нода пишем!
global_planner_node
Карта + A* + Pure Pursuit
Публикует: /cmd_vel, /map
↔
RViz готовое
Визуализация
Показывает карту и путь
Отправляет: /goal_pose

Ограничения

Запрещено использовать готовые навигационные стеки: Nav2, move_base, navigation2. Только rclcpp и стандартные типы сообщений ROS2.

Робот не знает карту заранее — строит её в реальном времени из данных лидара. Неизвестные клетки считаются проходимыми (для исследования).
