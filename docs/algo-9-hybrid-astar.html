Hybrid A*

Алгоритм №9 — A* с учётом физики: руль, скорость, кинематика

О чём вообще речь

Обычный A* — это пешеход: может шагнуть в любую из 8 соседних клеток, развернуться на месте. Hybrid A* — это автомобиль: у него есть руль, минимальный радиус поворота, он не умеет ходить боком. Маршрут на сетке прокладывается не из клетки в клетку, а по плавным дугам, которые робот реально способен проехать.

Hybrid A* — алгоритм планирования для неголономных роботов (машины, TurtleBot, вилочные погрузчики). Состояние — не просто $(x, y)$, а $(x, y, \theta)$, где $\theta$ — угол поворота. Переходы — реальные маневры с конечным радиусом поворота.

Сетка используется только для дискретизации: в каждой ячейке хранится лучшее непрерывное состояние. Это гибрид дискретного поиска (A*) и непрерывной кинематики.

Пространство состояний

Обычный A*

Состояние: $(x, y) \in \mathbb{Z}^2$

8 соседей, шаг = 1 клетка

Разворот на месте — бесплатно

Hybrid A*

Состояние: $(x, y, \theta) \in \mathbb{R}^2 \times [0, 2\pi)$

3–7 управляющих входов (руль)

Минимальный радиус поворота $R_{min}$

Модель велосипеда (bicycle model)

Кинематика TurtleBot3 и автомобилей описывается одинаково:

$$\dot{x} = v \cos\theta, \quad \dot{y} = v \sin\theta, \quad \dot{\theta} = \frac{v}{L} \tan\delta$$

Где $v$ — скорость, $L$ — колёсная база, $\delta$ — угол руля. Дискретизируем с шагом $\Delta t$:

$$x' = x + \Delta s \cdot \cos\theta, \quad y' = y + \Delta s \cdot \sin\theta, \quad \theta' = \theta + \frac{\Delta s}{L} \tan\delta$$

Управляющие входы

На каждом шаге робот выбирает один из нескольких маневров:

Маневр$\delta$ (руль)Результат
Прямо$0$Едем по прямой на $\Delta s$
Лево$+\delta_{max}$Дуга влево с радиусом $R_{min}$
Право$-\delta_{max}$Дуга вправо с радиусом $R_{min}$
Лёгкий лево$+\delta_{max}/2$Плавная дуга влево
Лёгкий право$-\delta_{max}/2$Плавная дуга вправо

Больше вариантов → плавнее путь, но медленнее поиск. Обычно 3–5 хватает.

Как работает алгоритм

1
Дискретизация. Разбиваем $(x,y)$ на сетку (как OccupancyGrid), $\theta$ — на $N_\theta$ секторов (обычно 36–72, т.е. шаг 5°–10°).
2
Инициализация. Стартовое состояние $(x_0, y_0, \theta_0)$ в open list. Ячейка сетки = $(i, j, k)$ где $k = \lfloor\theta / \Delta\theta\rfloor$.
3
Expand. Для текущего состояния применяем каждый маневр → получаем 3–5 новых состояний $(x', y', \theta')$.
4
Collision check. Проверяем, что дуга от $(x,y)$ до $(x',y')$ не пересекает препятствия (с учётом footprint робота).
5
Discretize & store. Вычисляем ячейку $(i', j', k')$. Если в ней уже есть состояние с меньшим $g$ — пропускаем. Иначе сохраняем.
6
Analytic expansion. Периодически пробуем Reeds-Shepp/Dubins кривую напрямую к цели. Если она проходима — нашли путь!

Analytic expansion — ключевая оптимизация. Вместо того чтобы ползти по сетке до самого конца, мы каждые N итераций пробуем аналитическую кривую к цели. Это ускоряет финальную часть пути в десятки раз.

Эвристики

Hybrid A* использует две эвристики и берёт максимум:

$h_1$: Non-holonomic без препятствий

Длина кратчайшей Dubins/Reeds-Shepp кривой до цели, игнорируя стены. Учитывает кинематику, но не карту.

$h_1 = \text{DubinsLength}(\text{state}, \text{goal})$

$h_2$: Holonomic с препятствиями

Обычный A*/Dijkstra от цели по 2D сетке (без $\theta$). Учитывает стены, но не кинематику.

$h_2 = \text{2D\_Dijkstra}(x, y, \text{goal})$
$$h(s) = \max(h_1(s),\; h_2(s))$$

Максимум двух допустимых эвристик — тоже допустимая эвристика, но более «тугая» (ближе к реальности).

Визуальный пример

На нашей карте 5×5 Hybrid A* не просто прыгает по клеткам — он рисует плавные дуги с учётом ориентации робота.

A* — ступенчатый путь

Hybrid A* — плавные дуги

Слева: A* — ступеньки, робот не может так ехать. Справа: Hybrid A* — плавная кривая, реальная траектория.

Псевдокод

function HybridAStar(start, goal, grid):
    open ← priority_queue()
    open.push(start, f = h(start))
    visited[discretize(start)] ← start

    while open не пуст:
        cur ← open.pop_min()

        // Analytic expansion: пробуем кривую напрямую к цели
        if попытка % 5 == 0:
            curve ← ReedsShepp(cur, goal)
            if collision_free(curve):
                return path(cur) + curve

        // Expand: применяем каждый маневр
        for δ ∈ {-δ_max, -δ_max/2, 0, +δ_max/2, +δ_max}:
            next ← simulate(cur, δ, Δs)
            cell ← discretize(next)  // (i, j, k_θ)

            if !collision_free(arc(cur, next)): continue
            if cell ∈ visited and visited[cell].g ≤ next.g: continue

            next.g ← cur.g + arc_length
            next.f ← next.g + max(h_dubins(next), h_2d(next))
            next.parent ← cur
            visited[cell] ← next
            open.push(next)

    return null

Реализация в C++ (ROS2)

Ключевые структуры: 3D-состояние, кинематическая модель, analytic expansion.

// --- hybrid_astar.hpp ---
#include <nav_msgs/msg/occupancy_grid.hpp>
#include <ompl/base/spaces/ReedsSheppStateSpace.h>

struct State3D {
    double x, y, theta;
    double g = 0, f = 0;
    State3D* parent = nullptr;
    int ix() const { return (int)(x / resolution); }
    int iy() const { return (int)(y / resolution); }
    int itheta() const { return (int)(theta / angle_res) % N_THETA; }
};

// Кинематическая модель (bicycle)
State3D simulate(const State3D& s, double delta, double ds) {
    State3D n;
    n.x = s.x + ds * cos(s.theta);
    n.y = s.y + ds * sin(s.theta);
    n.theta = normalize_angle(s.theta + ds / L * tan(delta));
    return n;
}

// Analytic expansion: Reeds-Shepp кривая к цели
std::optional<Path> try_analytic(const State3D& cur, const State3D& goal) {
    auto rs = ompl::base::ReedsSheppStateSpace(R_min);
    double len = rs.distance(to_ompl(cur), to_ompl(goal));
    Path path = rs.interpolate(to_ompl(cur), to_ompl(goal), len);
    if (collision_free(path))
        return path;
    return std::nullopt;
}

ROS2 Nav2: Hybrid A* реализован в nav2_smac_planner (плагин SmacPlannerHybrid). Настраивается через параметры: minimum_turning_radius, angle_quantization_bins, analytic_expansion_ratio.

Когда использовать

Идеально для:

  • Автомобили, вилочные погрузчики, Ackermann-роботы
  • Парковка и маневрирование в тесных пространствах
  • Когда путь должен быть сразу проезжаемым (без smoothing)
  • Nav2 SmacPlannerHybrid

Не подходит для:

  • Всенаправленные роботы (omnidirectional) — для них обычный A* лучше
  • Очень большие карты без аналитического расширения (медленно)
  • Дроны / манипуляторы (нужен 6-DOF, не 3-DOF)
