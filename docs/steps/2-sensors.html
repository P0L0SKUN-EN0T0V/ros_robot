Шаг 2: Глаза робота

Одометрия и лидар — откуда робот знает, где он и что вокруг

Два источника информации

У нашего робота нет камеры (в модели burger). Зато есть два «органа чувств»:

СенсорЧто даётТопикАналогия
Одометрия Позиция (x, y) и направление (yaw) /odom GPS + компас
Лидар Расстояния до объектов вокруг /scan Ультразвуковой дальномер, только лазерный и на 360°

Одометрия (Odometry)

Одометрия — данные о положении и ориентации робота в пространстве. Считается по оборотам колёс: если колесо повернулось на N оборотов, значит робот проехал X метров.
Представь, что ты идёшь с закрытыми глазами. Ты считаешь шаги и повороты: «10 шагов вперёд, поворот направо на 90°, ещё 5 шагов». Можешь примерно понять, где ты. Но со временем ошибка копится — и ты «уплываешь» от реальной позиции. Одометрия работает так же.

Что приходит в /odom

Сообщение типа nav_msgs/msg/Odometry. Нас интересуют три вещи:

// Позиция робота в метрах
pose.pose.position.x  →  1.523   // вперёд-назад
pose.pose.position.y  →  -0.847  // влево-вправо

// Ориентация (кватернион) — куда «смотрит» робот
pose.pose.orientation.x  →  0.0
pose.pose.orientation.y  →  0.0
pose.pose.orientation.z  →  0.383
pose.pose.orientation.w  →  0.924

Что за кватернион?

Ориентация приходит в виде кватерниона — четвёрки чисел (x, y, z, w). Это математический способ хранить вращение. Нам не нужно понимать математику — нужно только извлечь угол yaw (поворот вокруг вертикальной оси).

yaw = atan2(2 * (w * z + x * y), 1 - 2 * (y² + z²))

В ROS2 есть готовая функция, чтобы не считать руками:

// C++ — извлекаем yaw из кватерниона
#include <tf2/utils.h>

// В callback одометрии:
void odomCallback(const nav_msgs::msg::Odometry::SharedPtr msg) {
    double x   = msg->pose.pose.position.x;
    double y   = msg->pose.pose.position.y;

    // Извлекаем угол yaw (в радианах, от -π до +π)
    tf2::Quaternion q(
        msg->pose.pose.orientation.x,
        msg->pose.pose.orientation.y,
        msg->pose.pose.orientation.z,
        msg->pose.pose.orientation.w
    );
    double yaw = tf2::getYaw(q);

    // Теперь мы знаем: робот в точке (x, y), смотрит под углом yaw
}

yaw = 0 → робот смотрит вправо (по оси X).
yaw = π/2 ≈ 1.57 → смотрит вверх (по оси Y).
yaw = π ≈ 3.14 → смотрит влево.
yaw = -π/2 ≈ -1.57 → смотрит вниз.

Лидар (LiDAR)

Лидар (Light Detection and Ranging) — лазерный дальномер, который крутится на 360° и измеряет расстояние до ближайших объектов в каждом направлении. На TurtleBot3 burger — это плоский 2D-лидар (один горизонтальный слой лучей).
Представь, что ты стоишь в тёмной комнате с фонариком. Ты медленно поворачиваешься на 360° и каждый градус записываешь: «на 0° — стена в 2 метрах, на 1° — стена в 2.1 м, на 90° — дверной проём, ничего не видно (inf)». Вот это и делает лидар, только 10 раз в секунду.

Что приходит в /scan

sensor_msgs/msg/LaserScan:
  angle_min:       -3.14159   ← начало: -180° (сзади слева)
  angle_max:        3.14159   ← конец:  +180° (сзади справа)
  angle_increment:  0.01745   ← шаг: ~1° между лучами
  range_min:        0.12      ← ближе этого лидар не видит
  range_max:        3.50      ← дальше этого не видит
  ranges:          [0.50, 0.52, 0.51, ..., inf, ..., 1.23]
                   ↑ массив из ~360 чисел

Как читать массив ranges

Массив ranges — главная ценность. Каждый элемент — расстояние в метрах. Индекс определяет направление:

angle_i = angle_min + i * angle_increment

Пример: если angle_min = -π и angle_increment = 0.01745 (~1°), то:

Индекс iУголНаправлениеranges[i]
0-180°Прямо сзади0.50 м
90-90°Справа1.20 м
1800°Прямо вперёдinf (пусто)
270+90°Слева2.30 м
359+179°Почти сзади0.48 м

Внимание: значения inf (бесконечность) и nan — это нормально. inf = луч не попал ни в какой объект в пределах range_max. nan = ошибка измерения. Оба нужно фильтровать в коде.

Визуально: как лидар «видит» комнату

Из луча лидара в координаты на карте

Лидар даёт расстояние и угол. Но для карты нужны координаты (x, y) в мировой системе. Пересчёт:

1
Угол луча в мировой СК
world_angle = yaw + angle_min + i * angle_increment

yaw — куда смотрит робот (из одометрии), остальное — из LaserScan.

2
Координаты точки попадания
hit_x = robot_x + ranges[i] * cos(world_angle)
hit_y = robot_y + ranges[i] * sin(world_angle)
3
Из метров в клетки карты
cell_x = (int)((hit_x - map_origin_x) / resolution)
cell_y = (int)((hit_y - map_origin_y) / resolution)

Где resolution — размер клетки в метрах (обычно 0.05 = 5 см).

Этот пересчёт — основа функции updateMapWithLaser, которую мы напишем в следующем шаге.

Код: подписки на /scan и /odom

Вот как в нашей ноде будут выглядеть callback-функции:

// Храним последнюю позицию робота
double robot_x_ = 0.0, robot_y_ = 0.0, robot_yaw_ = 0.0;

// Callback одометрии — вызывается ~30 раз/сек
void odomCallback(const nav_msgs::msg::Odometry::SharedPtr msg) {
    robot_x_ = msg->pose.pose.position.x;
    robot_y_ = msg->pose.pose.position.y;

    tf2::Quaternion q(
        msg->pose.pose.orientation.x,
        msg->pose.pose.orientation.y,
        msg->pose.pose.orientation.z,
        msg->pose.pose.orientation.w
    );
    robot_yaw_ = tf2::getYaw(q);
}

// Callback лидара — вызывается ~10 раз/сек
void scanCallback(const sensor_msgs::msg::LaserScan::SharedPtr msg) {
    for (size_t i = 0; i < msg->ranges.size(); i++) {
        float r = msg->ranges[i];

        // Фильтруем невалидные значения
        if (std::isinf(r) || std::isnan(r) || r < msg->range_min || r > msg->range_max) {
            continue;
        }

        // Угол этого луча в мировой СК
        double angle = robot_yaw_ + msg->angle_min + i * msg->angle_increment;

        // Координаты точки попадания (в метрах)
        double hit_x = robot_x_ + r * cos(angle);
        double hit_y = robot_y_ + r * sin(angle);

        // Дальше — обновляем карту (следующий шаг)
        // updateMapWithLaser(robot_x_, robot_y_, hit_x, hit_y);
    }
}

Что происходит: Gazebo публикует /scan и /odom. Наша нода подписана на оба. Каждый раз, когда приходит новое сообщение, вызывается соответствующий callback. Мы сохраняем позицию робота и обрабатываем лучи лидара. Всё асинхронно — ROS2 сам вызывает наши функции в нужный момент.

ros2 topic hz /scan      # покажет ~5-10 Hz
ros2 topic hz /odom      # покажет ~30 Hz

Итоги шага

Теперь ты понимаешь:

  • Одометрия даёт позицию (x, y) и направление (yaw) робота.
  • Лидар даёт массив расстояний — 360° вокруг робота.
  • Из угла луча + расстояния можно вычислить точные координаты препятствия на карте.
  • Данные приходят автоматически через callback-функции — мы только подписываемся.

В следующем шаге используем эти данные, чтобы построить карту на ходу — клетка за клеткой, луч за лучом.
