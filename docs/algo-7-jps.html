Jump Point Search

Алгоритм №7 — A* на стероидах: прыгаем через скучные клетки

О чём вообще речь

Проблема A*: слишком много бесполезной работы

Представь карту 100×100 без единой стены. Тебе нужно пройти из угла в угол. Путь очевиден — прямая диагональ. Но A* этого не знает. Он берёт стартовую клетку, кладёт в очередь 8 соседей. Берёт лучшего соседа — кладёт его 8 соседей. И так далее. К моменту, когда A* дойдёт до цели, в очереди побывает несколько тысяч клеток. Каждую вставку в очередь — это O(log n) операция. Тысячи раз. На пустом поле.

Почему так? Потому что A* не умеет отличать скучные клетки от интересных. Для него каждый сосед — потенциально важный. Даже если вокруг километр пустоты.

Идея JPS: не клади в очередь, если ничего не изменилось

JPS задаёт простой вопрос: «А есть ли вообще смысл останавливаться на этой клетке?»

Если вокруг клетки пустота — смысла нет. Любой путь, проходящий через неё, можно точно так же провести через её соседей. Она ничего не решает, ни на что не влияет. Зачем тратить на неё время?

Совсем другое дело, когда рядом стена. Стена ломает симметрию: теперь не все пути равноценны. Клетка рядом со стеной — это развилка, точка принятия решения. Здесь маршрут реально может измениться.

Представь, что ты летишь на дроне над полем и ищешь дорогу к цели. Посреди пустого поля останавливаться незачем — ты просто летишь прямо. Но вот впереди забор. Тут нужно решить: обойти слева или справа? Именно в этой точке — у забора — ты останавливаешься и думаешь. JPS работает так же: пролетает пустоту, останавливается только у «заборов».
JPS = A*, который не тратит время на пустоту.
Он не меняет сам поиск — та же очередь с приоритетами, та же формула $f = g + h$. Единственная разница: вместо «положи всех 8 соседей в очередь» — «просканируй прямую линию, в очередь положи только точку у стены». Путь получается тот же самый, но работы в 10–30 раз меньше.

Что значит «сканировать»?

Когда JPS смотрит в направлении (допустим, вправо →), он не кладёт каждую клетку в очередь. Он запускает простой цикл while: шаг, шаг, шаг… Проверяет каждую клетку одним if: «рядом есть стена?». Если нет — шаг дальше. Если да — вот тут стоп, это jump point, кладём в очередь.

Этот цикл — дешёвый. Это не «добавить в очередь, отсортировать, достать минимум». Это просто бег по массиву. Разница — как между пролистать книгу и перепечатать каждую страницу.

А если стена сплошная? Он не застрянет?

Нет. JPS не «идёт к стене». Он смотрит в направлении стены. Если луч упирается в стену — он просто возвращает null (ничего не нашёл) и алгоритм пробует другое направление. Это как посмотреть в бинокль и увидеть тупик — ты же не побежишь в тупик, ты просто посмотришь в другую сторону.

Если стена длинная (занимает весь столбец) — луч пролетит вдоль неё, не найдёт ни одного «угла» где стена заканчивается, вернёт null. JPS попробует обойти стену через другую сторону карты. Результат всегда будет тот же, что у A* — просто быстрее.

Важно: JPS работает только на uniform-cost сетках (все проходимые клетки стоят одинаково) и использует 8 направлений движения — 4 кардинальных + 4 диагональных. Стоимость кардинального шага = 1, диагонального = $\sqrt{2} \approx 1.4$.

Три ключевых понятия

1. Natural neighbors — естественные соседи

Когда ты идёшь вправо по коридору, единственный «полезный» сосед — клетка справа. Все остальные направления (назад, вверх-назад, вниз-назад) твой родитель мог обработать не хуже тебя. Зачем дублировать работу?

Для кардинального движения (→): natural neighbor — только клетка впереди (→). Из 8 соседей оставляем 1.

Для диагонального движения (↘): natural neighbors — клетка по диагонали (↘) и обе её компоненты (→ и ↓). Из 8 соседей оставляем 3.

2. Forced neighbors — вынужденные соседи

А что если рядом с коридором стена? Допустим, ты идёшь вправо →, а снизу — стена. Клетка справа-снизу ↘ теперь не может быть достигнута «в обход» (через нижний ряд), потому что стена мешает. Единственный путь туда — через тебя. Эта клетка — forced neighbor. Она «заставляет» JPS остановиться и обратить внимание.

Формально: сосед $n$ узла $x$ является forced, если:

  • $n$ — не natural neighbor (обычно его бы пропустили)
  • Но прямой путь к $n$, минуя $x$, заблокирован стеной

Простым языком: forced neighbor появляется, когда стена ломает симметрию и заставляет тебя «свернуть». Это сигнал: здесь — jump point.

3. Jump point — точка прыжка

Jump point — клетка, где происходит что-то интересное. Формально:

$$y = \text{jump}(x, \vec{d}) \iff y = G \;\;\lor\;\; \exists\; \text{forced neighbor}(y)$$

Простым языком: прыгаем из $x$ в направлении $\vec{d}$, пока не случится одно из трёх — нашли цель, нашли forced neighbor или упёрлись в стену. Первые два — jump point, третий — тупик.

Для диагонального прыжка есть дополнительное правило: на каждом шаге по диагонали мы пускаем «лучи» по горизонтали и вертикали. Если хоть один луч нашёл jump point — текущая позиция тоже jump point. Так диагональ «подхватывает» интересные точки с боков.

Правила прунинга

Кардинальный прыжок (→ ← ↑ ↓)

Если пришли в $x$ горизонтально вправо →:

  • Natural: продолжаем вправо → (1 направление)
  • Forced: если стена снизу-слева → forced сосед снизу-справа ↘. Аналогично сверху
  • Pruned: все остальные 5–6 направлений — родитель достигнет их не хуже

Диагональный прыжок (↘ ↗ ↙ ↖)

Если пришли по диагонали ↘ (dx=+1, dy=+1):

  • Natural: ↘, → и ↓ (диагональ + обе компоненты = 3 направления)
  • Forced: если стена слева (x−1, y) → forced ↙; если стена сверху (x, y−1) → forced ↗
  • Pruned: ←, ↑, ↖ (достижимы из родителя)

Ключевое: на каждом шаге диагонального прыжка сначала пускаем горизонтальный и вертикальный «лучи». Если хоть один нашёл jump point — текущая клетка тоже становится jump point.

Как работает: пошагово

JPS — это тот же A*, но с другой функцией получения соседей. Вместо «все 8 соседей» — «только jump points в нужных направлениях».

1
Старт. Помещаем $S$ в open list с $g=0$, $f = h(S)$. Из старта рассматриваем все 8 направлений.
2
Выбираем. Достаём узел $x$ с минимальным $f = g + h$ из open list.
3
Pruning. Определяем направление, из которого пришли в $x$. Оставляем только natural + forced neighbors (1–5 направлений вместо 8).
4
Jump. Для каждого оставшегося направления $\vec{d}$ вызываем jump(x, d). Функция «летит» по прямой, пока не найдёт jump point, стену или край карты.
5
Добавляем. Каждый найденный jump point добавляем в open list: $g_{\text{new}} = g(x) + \text{dist}(x, \text{jp})$.
6
Повтор. Возвращаемся к шагу 2, пока не достигнем $G$ или open list пуст.

Анимация: как думает JPS

Жми ▶ или листай шаги вручную. Оранжевый — текущий узел, пунктир — лучи сканирования, зелёный — найденный jump point.

Почему именно эти точки — jump points?

Разберём каждый шаг. Для каждого — мини-карта: ● текущая позиция, ⇢ направление лучей, ▓ стена, которая всё меняет.

JPS раскрыл 5 узлов вместо ~18 у A*. Каждый jump point — это место, где стена «ломает» привычный маршрут и заставляет JPS обратить внимание. Нет стены рядом — нет jump point — прыгаем дальше.

Псевдокод

// JPS — отличие от A* только в получении соседей
function JPS(start, goal, grid):
    open ← priority_queue()
    open.push(start, f = h(start))
    g[start] ← 0

    while open не пуст:
        x ← open.pop_min()
        if x == goal: return reconstruct_path(x)

        for d ∈ pruned_directions(x):
            jp ← jump(x, d, goal, grid)
            if jp ≠ null:
                new_g ← g[x] + dist(x, jp)
                if new_g < g[jp]:
                    g[jp] ← new_g
                    parent[jp] ← x
                    open.push(jp, f = new_g + h(jp))

    return null  // пути нет

function jump(x, d, goal, grid):
    n ← x + d
    if !walkable(n): return null
    if n == goal: return n

    // есть forced neighbor? → это jump point
    if has_forced_neighbor(n, d): return n

    // диагональ: проверяем горизонтальный и вертикальный лучи
    if d is diagonal:
        if jump(n, horizontal(d), goal) ≠ null: return n
        if jump(n, vertical(d), goal) ≠ null: return n

    return jump(n, d, goal, grid)  // продолжаем прыгать

Реализация в C++ (ROS2)

JPS — надстройка над A*. Меняется только способ получения соседей. Ниже — две ключевые функции: проверка forced neighbors и рекурсивный прыжок.

// --- jump_point_search.hpp ---
#include <queue>
#include <vector>
#include <cmath>
#include <optional>

bool walkable(const nav_msgs::msg::OccupancyGrid& grid,
              int x, int y) {
    if (x < 0 || y < 0 ||
        x >= (int)grid.info.width ||
        y >= (int)grid.info.height)
        return false;
    return grid.data[y * grid.info.width + x] == 0;
}

// Проверка forced neighbors
bool has_forced(const OccupancyGrid& g,
                int x, int y, int dx, int dy) {
    if (dx != 0 && dy == 0) {
        // горизонтальное движение
        return (!walkable(g, x, y-1) && walkable(g, x+dx, y-1)) ||
               (!walkable(g, x, y+1) && walkable(g, x+dx, y+1));
    }
    if (dx == 0 && dy != 0) {
        // вертикальное движение
        return (!walkable(g, x-1, y) && walkable(g, x-1, y+dy)) ||
               (!walkable(g, x+1, y) && walkable(g, x+1, y+dy));
    }
    // диагональное движение
    return (!walkable(g, x-dx, y) && walkable(g, x-dx, y+dy)) ||
           (!walkable(g, x, y-dy) && walkable(g, x+dx, y-dy));
}

// Рекурсивный прыжок
std::optional<std::pair<int,int>>
jump(const OccupancyGrid& grid,
     int x, int y, int dx, int dy,
     int gx, int gy) {
    int nx = x + dx, ny = y + dy;
    if (!walkable(grid, nx, ny)) return std::nullopt;
    if (nx == gx && ny == gy) return {{nx, ny}};

    if (has_forced(grid, nx, ny, dx, dy))
        return {{nx, ny}};

    // Диагональ: проверяем компоненты
    if (dx != 0 && dy != 0) {
        if (jump(grid, nx, ny, dx, 0, gx, gy) ||
            jump(grid, nx, ny, 0, dy, gx, gy))
            return {{nx, ny}};
    }
    return jump(grid, nx, ny, dx, dy, gx, gy);
}

ROS2-нюанс: JPS работает только с бинарной OccupancyGrid (свободно / занято). Для costmap с inflation (разная стоимость проезда) используй обычный A* или JPS+ с предобработкой.

Сложность

МетрикаЗначениеЧто это значит
Время (worst case) $O(V \log V)$ В худшем случае (лабиринт) — как обычный A*
Время (типичное) $O(k \log k),\; k \ll V$ $k$ = число jump points. На открытых картах в 10–100× меньше $V$
Память $O(V)$ Массив visited + open list — как у A*
Один прыжок $O(\sqrt{V})$ Максимум — длина стороны карты

Когда использовать

Идеально для:

  • Большие uniform-cost карты (склады, open world, игры)
  • Статические или редко меняющиеся карты
  • Когда A* слишком медленный, но нужна гарантия оптимальности
  • Массовый pathfinding — сотни агентов на одной карте

Не подходит:

  • Взвешенные карты (costmap с разной стоимостью проезда)
  • Непрерывное пространство (используй RRT/PRM)
  • Динамическая среда (лучше D* Lite)
  • Нужно строго 4-направленное движение (JPS заточен под 8)

Продвинутые варианты

JPS+ (с предобработкой)

Для каждой клетки заранее вычисляется расстояние до ближайшего jump point в каждом из 8 направлений. Прыжок jump() становится $O(1)$ вместо $O(\sqrt{V})$, но нужна предобработка $O(V)$. Подходит для статических карт, где ничего не меняется.

JPS(B) — Block-based

Разбивает карту на блоки, использует bitwise-операции для ускорения прыжков. Ещё 2–4× быстрее поверх JPS+. Для тех, кому мало «в 30 раз быстрее A*».
