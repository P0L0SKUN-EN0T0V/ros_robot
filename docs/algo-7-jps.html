Jump Point Search

Алгоритм №7 — A* на стероидах: прыгаем через скучные клетки

О чём вообще речь

Представь, что идёшь по длинному прямому коридору. Обычный A* останавливается на каждой плитке пола: «так, эта тоже проходима… и эта… и эта…». JPS не такой зануда — он пробегает весь коридор одним прыжком и останавливается только у поворота или у двери. Итог тот же — оптимальный путь, но без бесполезного перебора «скучных» клеток.

Jump Point Search (JPS) — это оптимизация A* для uniform-cost сеток. Он не меняет сам алгоритм поиска, а радикально сокращает количество узлов в open list, «прыгая» через клетки, которые можно безопасно пропустить.

Ключевая идея: если сосед доступен из родителя напрямую (без обхода препятствий) — его не надо добавлять в очередь. Мы добавляем только jump points — клетки у поворотов, рядом с препятствиями и на целевой позиции.

A*

Раскрывает 15–20 узлов на карте 5×5

Добавляет каждого соседа в open list

JPS

Раскрывает 3–5 jump points на той же карте

Пропускает все «скучные» клетки за один прыжок

Три ключевых понятия

1. Natural Neighbors (естественные соседи)

Это те соседи узла $x$, до которых оптимальный путь обязательно проходит через $x$. Если мы пришли в $x$ горизонтально (слева), то естественный сосед — следующая клетка справа. Все остальные можно достичь не хуже через родителя $x$ напрямую.

2. Forced Neighbors (вынужденные соседи)

Forced neighbor — сосед, до которого путь через $x$ короче, чем обход мимо $x$. Это происходит, когда рядом с $x$ стоит стена и «заставляет» нас повернуть.

Формально: сосед $n$ узла $x$ является forced, если:

  • $n$ не является natural neighbor для $x$
  • $\text{len}(p(x) \to x \to n) < \text{len}(p(x) \to n)$ без прохода через $x$ (т.е. прямой путь заблокирован стеной)

3. Jump Point (точка прыжка)

Узел $y$ является jump point от $x$ в направлении $\vec{d}$, если:

$$y = \text{jump}(x, \vec{d}) \iff y = G \;\lor\; \exists \text{ forced neighbor}(y)$$

Иными словами: прыгаем в направлении $\vec{d}$ пока не встретим цель, forced neighbor или стену. Для диагональных прыжков дополнительно проверяем горизонтальный и вертикальный «лучи» на каждом шаге.

Как работает алгоритм

1
Инициализация. Добавляем старт $S$ в open list (как обычный A*).
2
Выбираем. Достаём узел $x$ с минимальным $f = g + h$ из open list.
3
Pruning. Вместо всех 8 соседей оставляем только natural + forced neighbors (обычно 1–3 направления вместо 8).
4
Jump. Для каждого оставшегося направления $\vec{d}$ вызываем $\text{jump}(x, \vec{d})$. Функция «летит» по прямой, пока не найдёт jump point, стену или выход за границу.
5
Добавляем. Каждый найденный jump point добавляем в open list с корректным $g$.
6
Повторяем шаги 2–5 пока не достигнем $G$ или open list пуст.

Результат — гарантированно оптимальный путь, как у A*. Но open list в разы меньше: на больших картах JPS может быть в 10× быстрее обычного A*.

Правила прунинга

Горизонтальный/вертикальный прыжок

Если пришли в $x$ горизонтально вправо →:

  • Natural: продолжаем вправо →
  • Forced: если стена сверху-слева от $x$ → forced neighbor сверху-справа ↗. Аналогично снизу.
  • Pruned: все остальные 5 направлений — до них родитель $x$ дойдёт не хуже

Диагональный прыжок

Если пришли по диагонали ↘:

  • Natural: ↘, → и ↓ (диагональ + обе компоненты)
  • Forced: если стена слева → ↙ forced; если стена сверху → ↗ forced
  • Pruned: ←, ↑, ↖ (уже были достижимы из родителя)

На каждом шаге диагонального прыжка сначала пускаем горизонтальный и вертикальный «лучи». Если хоть один из них нашёл jump point — текущая позиция тоже jump point.

Почему именно эти точки — jump points?

(1,1) — forced neighbor из-за стены (2,1). Прыгая из S вниз-вправо ↘, мы натыкаемся на то, что клетка (2,1) заблокирована. Значит (1,1) — jump point: здесь приходится менять направление.

(2,3) — forced neighbor из-за стены (2,2). Прыгая вниз-вправо ↘ от (1,1), через (3,2), горизонтальный луч вправо из (2,3) обнаруживает, что слева стена. Это forced neighbor → jump point.

(3,2) — промежуточный jump point. Диагональный прыжок ↘ из (1,1): на шаге (3,2) горизонтальный луч → находит (2,3) как jump point. Поэтому (3,2) тоже маркируется.

G(4,4) — цель всегда является jump point по определению.

Псевдокод

// Jump Point Search — отличие от A* только в identify_successors
function JPS(start, goal, grid):
    open ← priority_queue()
    open.push(start, f=h(start))
    g[start] ← 0

    while open не пуст:
        x ← open.pop_min()
        if x == goal: return reconstruct_path(x)

        for каждого направления d ∈ pruned_neighbors(x):
            jp ← jump(x, d, goal, grid)
            if jp ≠ null:
                new_g ← g[x] + dist(x, jp)
                if new_g < g[jp]:
                    g[jp] ← new_g
                    parent[jp] ← x
                    open.push(jp, f = new_g + h(jp))

    return null  // пути нет

function jump(x, d, goal, grid):
    n ← x + d
    if !grid.walkable(n): return null
    if n == goal: return n

    // forced neighbor check
    if has_forced_neighbor(n, d): return n

    // для диагонали: проверяем горизонтальный и вертикальный лучи
    if d is diagonal:
        if jump(n, horizontal(d), goal) ≠ null: return n
        if jump(n, vertical(d), goal) ≠ null: return n

    return jump(n, d, goal, grid)  // рекурсия — продолжаем прыгать

Реализация в C++ (ROS2)

JPS — надстройка над A*. Меняется только функция получения соседей. Ниже — ключевые функции, остальной код A* остаётся без изменений.

// --- jump_point_search.hpp ---
#include <queue>
#include <vector>
#include <cmath>

struct Node {
    int x, y;
    double g, f;
    Node* parent = nullptr;
    bool operator>(const Node& o) const { return f > o.f; }
};

bool walkable(const nav_msgs::msg::OccupancyGrid& grid, int x, int y) {
    if (x < 0 || y < 0 || x >= (int)grid.info.width || y >= (int)grid.info.height)
        return false;
    return grid.data[y * grid.info.width + x] == 0;
}

// Проверка forced neighbors для горизонтального/вертикального движения
bool has_forced(const OccupancyGrid& g, int x, int y, int dx, int dy) {
    if (dx != 0 && dy == 0) {  // горизонтально
        return (!walkable(g, x, y-1) && walkable(g, x+dx, y-1)) ||
               (!walkable(g, x, y+1) && walkable(g, x+dx, y+1));
    }
    if (dx == 0 && dy != 0) {  // вертикально
        return (!walkable(g, x-1, y) && walkable(g, x-1, y+dy)) ||
               (!walkable(g, x+1, y) && walkable(g, x+1, y+dy));
    }
    // диагональ — forced если заблокирован «бок»
    return (!walkable(g, x-dx, y) && walkable(g, x-dx, y+dy)) ||
           (!walkable(g, x, y-dy) && walkable(g, x+dx, y-dy));
}

// Рекурсивный прыжок
Node* jump(const OccupancyGrid& grid, int x, int y,
           int dx, int dy, int gx, int gy) {
    int nx = x + dx, ny = y + dy;
    if (!walkable(grid, nx, ny)) return nullptr;
    if (nx == gx && ny == gy) return make_node(nx, ny);

    if (has_forced(grid, nx, ny, dx, dy))
        return make_node(nx, ny);

    // Диагональ: проверяем компоненты
    if (dx != 0 && dy != 0) {
        if (jump(grid, nx, ny, dx, 0, gx, gy) ||
            jump(grid, nx, ny, 0, dy, gx, gy))
            return make_node(nx, ny);
    }
    return jump(grid, nx, ny, dx, dy, gx, gy);
}

ROS2-интеграция: JPS работает только на 2D uniform-cost grid, т.е. напрямую с OccupancyGrid из /map. Для взвешенных карт (costmap с inflation) используй обычный A* или JPS+ с предобработкой.

Сложность

МетрикаЗначениеЧто это значит
Время (worst case) $O(V \log V)$ В худшем случае — как A* (лабиринт без длинных коридоров)
Время (типичное) $O(k \log k)$, $k \ll V$ $k$ = число jump points. На открытых картах $k$ может быть в 10–100× меньше $V$
Память $O(V)$ Как A* — нужен массив visited и open list
Прыжок (jump) $O(\sqrt{V})$ Один прыжок проходит не более стороны карты

Когда использовать

Идеально для:

  • Большие uniform-cost карты (склады, open world)
  • Статические или редко меняющиеся карты
  • Когда A* слишком медленный, но нужна оптимальность
  • Игровые NPC, массовый pathfinding для сотен агентов

Не подходит для:

  • Взвешенные карты (costmap с разной стоимостью проезда)
  • Непрерывное пространство (нужен RRT/PRM)
  • Динамическая среда (лучше D* Lite)
  • Карты с нецелочисленными координатами

Продвинутые варианты

JPS+ (с предобработкой)

Для каждой клетки заранее вычисляется расстояние до ближайшего jump point в каждом из 8 направлений. Это позволяет выполнить jump() за $O(1)$ вместо $O(\sqrt{V})$, но требует предобработки $O(V)$.

Подходит для статических карт, где topology не меняется.

JPS (B) — Block-based

Разбивает карту на блоки, использует bitwise-операции для ускорения прыжков. Даёт ещё 2–4× ускорение поверх JPS+.
