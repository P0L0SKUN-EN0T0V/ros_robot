1. Общая картина — что от нас хотят

Задача проекта в одном предложении:

Робот стартует в незнакомом мире. Он не знает карту. Ты ставишь ему цель в RViz — и он сам строит карту лидаром, прокладывает путь через A*, и едет по нему через Pure Pursuit.

Pipeline — как данные текут

→

→

→
Pure Pursuit

→
Робот едет

Параллельно:

→
Все алгоритмы

Ключевой момент: карта не дана заранее! Робот начинает с пустой сетки (все клетки = «неизвестно»). Лидар сканирует окружение → лучи отмечают свободные и занятые клетки → A* строит путь по тому, что уже известно. Неизвестные клетки считаются проходимыми — так робот может исследовать.

Три компонента системы

Gazebo (симулятор)

Виртуальный мир с роботом TurtleBot3. Публикует данные сенсоров: одометрию, лидар, TF-трансформации. Принимает команды скоростей.

Готов из коробки — ничего писать не надо.

Наш узел (навигация)

Один C++ узел global_planner_node. Подписывается на сенсоры, строит карту, планирует путь A*, управляет роботом через Pure Pursuit.

Это пишем мы — основная работа.

RViz (визуализация)

Показывает карту, путь, робота. Через «2D Goal Pose» ставим цель — клик мышкой.

Инструмент — настроить и использовать.

Шаг 1 — Одометрия: «где я?»

1

Цель: узнать текущую позицию робота (x, y, yaw)

Gazebo публикует позицию робота в топик /odom с частотой ~50 Гц. Нам нужно подписаться и извлечь три числа: координаты (x, y) и угол поворота (yaw).

Зачем: все остальные алгоритмы (карта, A*, Pure Pursuit) используют текущую позицию робота. Без одометрии ничего не работает.

Кватернион → yaw

Ориентация приходит как кватернион (x, y, z, w) — это 3D-поворот. Нам нужен только угол вокруг оси Z (yaw). Формула:

$$\text{yaw} = \text{atan2}\big(2(wz + xy),\ 1 - 2(y^2 + z^2)\big)$$

Код

// В конструкторе: подписка на /odom
odom_sub_ = this->create_subscription<nav_msgs::msg::Odometry>(
    "/odom", 10,
    [this](const nav_msgs::msg::Odometry::SharedPtr msg) {
        odomCallback(msg);
    });

// Callback
void GlobalPlannerNode::odomCallback(
    const nav_msgs::msg::Odometry::SharedPtr msg)
{
    std::lock_guard<std::mutex> lock(data_mutex_);
    current_x_ = msg->pose.pose.position.x;
    current_y_ = msg->pose.pose.position.y;

    // Кватернион → yaw
    auto& q = msg->pose.pose.orientation;
    current_yaw_ = std::atan2(
        2.0 * (q.w * q.z + q.x * q.y),
        1.0 - 2.0 * (q.y * q.y + q.z * q.z));
}

Добавь в callback строку RCLCPP_INFO(get_logger(), "x=%.2f y=%.2f yaw=%.2f", current_x_, current_y_, current_yaw_);

Запусти Gazebo + свой узел. В терминале должны бежать координаты. Покрути робота через ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{angular: {z: 0.5}}" — yaw должен меняться.

Шаг 2 — Лидар: «что вокруг?»

2

Цель: получить массив расстояний до препятствий

Лидар TurtleBot3 — это 360° лазерный сканер. Он посылает ~360 лучей и для каждого возвращает расстояние до ближайшего препятствия.

Структура LaserScan

ПолеТипЧто это
angle_minfloatНачальный угол (обычно 0 или -π)
angle_maxfloatКонечный угол (обычно 2π или π)
angle_incrementfloatШаг между лучами (~0.0175 рад ≈ 1°)
ranges[]float[]Массив расстояний — это главное
range_minfloatМин. дальность (< этого — шум)
range_maxfloatМакс. дальность (> этого — нет данных)

Код

// В конструкторе: подписка на /scan
scan_sub_ = this->create_subscription<sensor_msgs::msg::LaserScan>(
    "/scan", 10,
    [this](const sensor_msgs::msg::LaserScan::SharedPtr msg) {
        scanCallback(msg);
    });

// Callback — просто сохраняем данные
void GlobalPlannerNode::scanCallback(
    const sensor_msgs::msg::LaserScan::SharedPtr msg)
{
    std::lock_guard<std::mutex> lock(data_mutex_);
    scan_ranges_ = msg->ranges;

    // Сразу обновляем карту свежими данными лидара
    updateMapWithLaser();
}

Важно: ranges[i] может быть inf (луч улетел в пустоту) или nan (ошибка датчика). Всегда проверяй: if (r > range_min && r < range_max) перед использованием.

Как луч превращается в точку на карте

Каждый луч i имеет угол и расстояние. Глобальные координаты точки препятствия:

$$w_x = x_{\text{робот}} + r_i \cdot \cos(\text{yaw} + \alpha_i)$$

$$w_y = y_{\text{робот}} + r_i \cdot \sin(\text{yaw} + \alpha_i)$$

где $\alpha_i = \text{angle\_min} + i \cdot \text{angle\_increment}$

Добавь лог: RCLCPP_INFO(get_logger(), "scan: %zu rays, front=%.2f m", scan_ranges_.size(), scan_ranges_[0]);

Должно показывать ~360 лучей. Поставь препятствие перед роботом в Gazebo — front уменьшится.

Шаг 3 — Карта: «рисуем по ходу»

3

Цель: превратить лучи лидара в OccupancyGrid

Карта — это сетка клеток. Каждая клетка хранит одно из трёх значений:

⬜
0 — свободно
Луч прошёл сквозь
⬛
100 — стена
Луч упёрся сюда
❓
-1 — неизвестно
Луч сюда не доставал

Инициализация

// В конструкторе
map_data_.assign(map_width_ * map_height_, -1);  // всё неизвестно
map_origin_x_ = -(map_width_ * map_resolution_) / 2.0;   // центрируем карту
map_origin_y_ = -(map_height_ * map_resolution_) / 2.0;

updateMapWithLaser — ядро построения карты

Для каждого валидного луча:

  1. Вычисляем мировые координаты точки препятствия (формулы из Шага 2)
  2. Переводим в индексы карты: mx = (wx - origin_x) / resolution
  3. Помечаем клетку препятствия как 100
  4. Ray tracing: проходим по всем клеткам между роботом и препятствием, помечая их как 0 (свободно)
void GlobalPlannerNode::updateMapWithLaser() {
    if (scan_ranges_.empty()) return;

    double angle = -M_PI;  # angle_min для TurtleBot3
    double angle_inc = 2.0 * M_PI / scan_ranges_.size();

    for (size_t i = 0; i < scan_ranges_.size(); i++) {
        double r = scan_ranges_[i];
        if (r < 0.12 || r > 3.5 || std::isinf(r) || std::isnan(r)) {
            angle += angle_inc;
            continue;
        }

        // Мировые координаты конца луча
        double wx = current_x_ + r * std::cos(current_yaw_ + angle);
        double wy = current_y_ + r * std::sin(current_yaw_ + angle);

        // Индексы карты: робот и препятствие
        int rx = (int)((current_x_ - map_origin_x_) / map_resolution_);
        int ry = (int)((current_y_ - map_origin_y_) / map_resolution_);
        int mx = (int)((wx - map_origin_x_) / map_resolution_);
        int my = (int)((wy - map_origin_y_) / map_resolution_);

        // Ray tracing (Bresenham): свободные клетки между роботом и стеной
        int dx = std::abs(mx - rx), dy = std::abs(my - ry);
        int sx = (rx < mx) ? 1 : -1;
        int sy = (ry < my) ? 1 : -1;
        int err = dx - dy;
        int cx = rx, cy = ry;

        while (cx != mx || cy != my) {
            if (cx >= 0 && cx < map_width_ && cy >= 0 && cy < map_height_)
                map_data_[cy * map_width_ + cx] = 0;  // свободно
            int e2 = 2 * err;
            if (e2 > -dy) { err -= dy; cx += sx; }
            if (e2 <  dx) { err += dx; cy += sy; }
        }

        // Конец луча = препятствие
        if (mx >= 0 && mx < map_width_ && my >= 0 && my < map_height_)
            map_data_[my * map_width_ + mx] = 100;  // стена

        angle += angle_inc;
    }
}

Ray tracing (Bresenham) — алгоритм рисования линии по пикселям. Мы «рисуем линию» от робота до препятствия, помечая каждую клетку на пути как свободную. Это та же идея, что в Theta* (line of sight).

Шаг 4 — A*: «куда ехать?»

4

Цель: найти путь от робота до цели по текущей карте

Отличие от классического A*: карта — частичная. Робот ещё не видел большую часть мира. Поэтому неизвестные клетки (-1) считаются проходимыми — иначе робот не сможет исследовать.

Подробное описание A* с анимацией — на странице алгоритма. Здесь — адаптация под наш проект.

isFree — проходима ли клетка?

bool GlobalPlannerNode::isFree(int mx, int my) {
    if (mx < 0 || mx >= map_width_ || my < 0 || my >= map_height_)
        return false;
    int8_t val = map_data_[my * map_width_ + mx];
    return val == 0 || val == -1;  // свободно ИЛИ неизвестно
}

planAStar

struct AStarNode {
    int x, y;
    double g, h;
    int px, py;  // координаты родителя
    double f() const { return g + h; }
};

std::deque<std::pair<double,double>>
GlobalPlannerNode::planAStar(double sx, double sy,
                             double gx, double gy)
{
    // Мировые координаты → индексы карты
    int startX = (int)((sx - map_origin_x_) / map_resolution_);
    int startY = (int)((sy - map_origin_y_) / map_resolution_);
    int goalX  = (int)((gx - map_origin_x_) / map_resolution_);
    int goalY  = (int)((gy - map_origin_y_) / map_resolution_);

    // Безопасность: если старт на стене — пометить как free
    if (!isFree(startX, startY))
        map_data_[startY * map_width_ + startX] = 0;

    // Priority queue: min-heap по f
    auto cmp = [](const AStarNode& a, const AStarNode& b) {
        return a.f() > b.f();
    };
    std::priority_queue<AStarNode, std::vector<AStarNode>,
                        decltype(cmp)> open(cmp);

    // visited[y * width + x] = true
    std::vector<bool> visited(map_width_ * map_height_, false);
    std::vector<int> parent(map_width_ * map_height_, -1);

    auto heuristic = [](int x1, int y1, int x2, int y2) {
        return std::hypot(x2 - x1, y2 - y1);
    };

    open.push({startX, startY, 0.0,
               heuristic(startX, startY, goalX, goalY),
               -1, -1});

    // 8 направлений
    int dx[] = {1,-1,0,0, 1,1,-1,-1};
    int dy[] = {0,0,1,-1, 1,-1,1,-1};
    double dc[] = {1,1,1,1, 1.414,1.414,1.414,1.414};

    while (!open.empty()) {
        AStarNode cur = open.top(); open.pop();
        int idx = cur.y * map_width_ + cur.x;

        if (visited[idx]) continue;
        visited[idx] = true;
        parent[idx] = cur.py * map_width_ + cur.px;

        // Достигли цели?
        if (cur.x == goalX && cur.y == goalY) {
            // Восстановить путь
            std::deque<std::pair<double,double>> path;
            int ci = idx;
            while (ci != -1 && ci != cur.py * map_width_ + cur.px) {
                int py = ci / map_width_, px = ci % map_width_;
                path.push_front({
                    map_origin_x_ + (px + 0.5) * map_resolution_,
                    map_origin_y_ + (py + 0.5) * map_resolution_
                });
                ci = parent[ci];
            }
            return path;
        }

        // Раскрыть 8 соседей
        for (int d = 0; d < 8; d++) {
            int nx = cur.x + dx[d], ny = cur.y + dy[d];
            if (!isFree(nx, ny)) continue;
            if (visited[ny * map_width_ + nx]) continue;

            open.push({nx, ny, cur.g + dc[d],
                       heuristic(nx, ny, goalX, goalY),
                       cur.x, cur.y});
        }
    }

    RCLCPP_WARN(get_logger(), "A* failed: no path found");
    return {};  // нет пути
}

Вызов A* при получении цели

void GlobalPlannerNode::goalCallback(
    const geometry_msgs::msg::PoseStamped::SharedPtr msg)
{
    goal_x_ = msg->pose.position.x;
    goal_y_ = msg->pose.position.y;
    has_goal_ = true;

    global_plan_ = planAStar(current_x_, current_y_, goal_x_, goal_y_);

    if (!global_plan_.empty()) {
        RCLCPP_INFO(get_logger(), "Path found: %zu points", global_plan_.size());
        publishPath();
    }
}

Запусти всё, в RViz добавь дисплей Path (топик /global_plan). Кликни 2D Goal Pose — должна появиться линия пути от робота до цели. Путь обходит стены, которые робот уже увидел лидаром.

Шаг 5 — Pure Pursuit: «как ехать?»

5

Цель: робот едет по пути, плавно поворачивая

A* дал нам путь — набор точек. Pure Pursuit выбирает опорную точку на расстоянии lookahead вперёд по пути и рулит к ней.

Аналогия: ты ведёшь машину. Ты не смотришь себе под колёса — ты смотришь на дорогу метров на 5-10 вперёд. Вот это и есть lookahead distance.

Алгоритм

  1. Найти ближайшую к роботу точку пути
  2. Отмерить lookahead_dist (0.6 м) вперёд по пути
  3. Вычислить угол от робота до опорной точки
  4. Линейная скорость ∝ расстоянию до точки (макс 0.3 м/с)
  5. Угловая скорость ∝ угловой ошибке (макс ±0.8 рад/с)
void GlobalPlannerNode::purePursuitControl() {
    if (global_plan_.empty() || !has_goal_) return;

    constexpr double lookahead = 0.6;
    constexpr double max_linear = 0.3;
    constexpr double max_angular = 0.8;
    constexpr double Kp_ang = 1.5;

    // 1. Найти ближайшую точку
    double min_dist = 1e9;
    size_t closest = 0;
    for (size_t i = 0; i < global_plan_.size(); i++) {
        double d = std::hypot(global_plan_[i].first - current_x_,
                             global_plan_[i].second - current_y_);
        if (d < min_dist) { min_dist = d; closest = i; }
    }

    // 2. Отмерить lookahead вперёд по пути
    double acc = 0;
    size_t target = closest;
    for (size_t i = closest; i + 1 < global_plan_.size(); i++) {
        acc += std::hypot(global_plan_[i+1].first - global_plan_[i].first,
                          global_plan_[i+1].second - global_plan_[i].second);
        target = i + 1;
        if (acc >= lookahead) break;
    }

    double tx = global_plan_[target].first;
    double ty = global_plan_[target].second;

    // 3. Угол к опорной точке
    double angle_to_target = std::atan2(ty - current_y_, tx - current_x_);
    double angle_err = angle_to_target - current_yaw_;

    // Нормализация в [-π, π]
    while (angle_err >  M_PI) angle_err -= 2 * M_PI;
    while (angle_err < -M_PI) angle_err += 2 * M_PI;

    // 4. Команды скоростей
    double dist = std::hypot(tx - current_x_, ty - current_y_);
    double linear  = std::min(max_linear, dist);
    double angular = std::clamp(Kp_ang * angle_err, -max_angular, max_angular);

    // 5. Безопасность: если стена прямо впереди — стоп и поворот
    if (!scan_ranges_.empty() && scan_ranges_[0] < 0.35) {
        linear = 0;
        angular = 0.5;  // поворот от стены
    }

    // Достигли цели?
    if (std::hypot(goal_x_ - current_x_, goal_y_ - current_y_) < 0.15) {
        linear = 0; angular = 0;
        has_goal_ = false;
        RCLCPP_INFO(get_logger(), "Goal reached!");
    }

    geometry_msgs::msg::Twist cmd;
    cmd.linear.x = linear;
    cmd.angular.z = angular;
    cmd_vel_pub_->publish(cmd);
}

Кликни 2D Goal Pose — робот должен поехать по пути и остановиться у цели. Если путь проходит через неизвестную территорию, робот по дороге увидит новые стены → карта обновится → при следующем клике путь обойдёт их.

Шаг 6 — TF2 и координаты

6

Цель: чтобы RViz правильно показывал робота на карте

В ROS2 есть несколько систем координат (frames). Они связаны цепочкой трансформаций:

Gazebo публикует odom → base_footprint и base_footprint → laser_frame. Нам нужно добавить map → odom (в нашем проекте считаем их совпадающими — одометрия идеальная в симуляторе).

// В конструкторе: статическая трансформация map → odom
auto tf_broadcaster = std::make_shared<tf2_ros::StaticTransformBroadcaster>(this);
geometry_msgs::msg::TransformStamped t;
t.header.stamp = this->now();
t.header.frame_id = "map";
t.child_frame_id = "odom";
t.transform.rotation.w = 1.0;  // единичный кватернион = нет поворота
tf_broadcaster->sendTransform(t);

Зачем: без трансформации map → odom RViz не сможет отобразить робота на карте. Ты увидишь «Fixed Frame [map] does not exist» или робот будет в начале координат.
