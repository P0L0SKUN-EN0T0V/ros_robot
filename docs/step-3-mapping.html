Шаг 3: Рисуем карту на ходу

OccupancyGrid, ray tracing и функция updateMapWithLaser

Главная идея

Робот не знает карту заранее. Он начинает в полном тумане и открывает мир по мере движения — как в игре с «туманом войны».

Представь, что ты в тёмной комнате с фонариком. Ты светишь — видишь кусок стены впереди. Поворачиваешься — видишь дверь слева. Идёшь к двери — открываешь новый коридор. Постепенно в голове складывается карта помещения. Наш робот делает то же самое, но вместо фонарика — лидар.

Ray tracing: рисуем лучом по сетке

Каждый луч лидара говорит: «В направлении X на расстоянии R метров — стена». Но нам нужно обновить не только клетку стены, а все клетки между роботом и стеной — они же свободны (луч через них прошёл).

1
Начальная точка — позиция робота (клетка на сетке).
2
Конечная точка — место попадания луча (клетка стены).
3
Все клетки на линии между ними → помечаем как 0 (свободно).
4
Конечная клетка → помечаем как 100 (стена).
Представь, что ты смотришь сквозь ряд забора. Ты видишь стену в конце. Значит, все щели забора между тобой и стеной — пустые (луч прошёл), а в конце — стена (луч упёрся).

Алгоритм Брезенхэма

Как нарисовать линию на пиксельной сетке? Этот вопрос решили ещё в 1962 году. Алгоритм Брезенхэма (Bresenham's line) — быстрый способ перечислить все клетки на линии между двумя точками. Работает только с целыми числами (идеально для сетки).

Не нужно понимать его математику — просто знай, что он берёт две клетки (начало и конец) и возвращает список всех клеток на линии между ними. Мы используем его как «чёрный ящик».

Код: updateMapWithLaser

Это первая ключевая функция нашей ноды. Она вызывается для каждого луча лидара:

// Параметры карты
const int MAP_SIZE = 200;            // 200×200 клеток
const double RESOLUTION = 0.05;      // 5 см на клетку
const double ORIGIN_X = -5.0;        // карта начинается с -5 м
const double ORIGIN_Y = -5.0;

std::vector<int8_t> map_data_(MAP_SIZE * MAP_SIZE, -1);  // всё неизвестно

// Преобразование: метры → индекс клетки
int worldToGrid(double coord, double origin) {
    return static_cast<int>((coord - origin) / RESOLUTION);
}

// Основная функция: обновить карту одним лучом
void updateMapWithLaser(double rx, double ry, double hx, double hy) {
    // rx,ry = позиция робота (метры)
    // hx,hy = точка попадания луча (метры)

    int x0 = worldToGrid(rx, ORIGIN_X);
    int y0 = worldToGrid(ry, ORIGIN_Y);
    int x1 = worldToGrid(hx, ORIGIN_X);
    int y1 = worldToGrid(hy, ORIGIN_Y);

    // Проверяем границы
    if (x1 < 0 || x1 >= MAP_SIZE || y1 < 0 || y1 >= MAP_SIZE) return;

    // === Алгоритм Брезенхэма ===
    int dx = abs(x1 - x0), dy = abs(y1 - y0);
    int sx = (x0 < x1) ? 1 : -1;
    int sy = (y0 < y1) ? 1 : -1;
    int err = dx - dy;

    int cx = x0, cy = y0;
    while (cx != x1 || cy != y1) {
        // Все клетки на пути луча — свободны
        if (cx >= 0 && cx < MAP_SIZE && cy >= 0 && cy < MAP_SIZE) {
            map_data_[cy * MAP_SIZE + cx] = 0;   // свободно
        }

        int e2 = 2 * err;
        if (e2 > -dy) { err -= dy; cx += sx; }
        if (e2 <  dx) { err += dx; cy += sy; }
    }

    // Последняя клетка — стена
    map_data_[y1 * MAP_SIZE + x1] = 100;  // занято
}

Порядок индексации: map_data_ — одномерный массив размером MAP_SIZE × MAP_SIZE. Клетка (x, y) хранится по индексу y * MAP_SIZE + x. Это стандарт ROS2 для OccupancyGrid.

Интеграция в scanCallback

Теперь подключим updateMapWithLaser к callback-у лидара из предыдущего шага:

void scanCallback(const sensor_msgs::msg::LaserScan::SharedPtr msg) {
    for (size_t i = 0; i < msg->ranges.size(); i++) {
        float r = msg->ranges[i];

        // Пропускаем невалидные
        if (std::isinf(r) || std::isnan(r)) continue;
        if (r < msg->range_min || r > msg->range_max) continue;

        // Угол луча в мировой СК
        double angle = robot_yaw_ + msg->angle_min + i * msg->angle_increment;

        // Координаты точки попадания
        double hit_x = robot_x_ + r * cos(angle);
        double hit_y = robot_y_ + r * sin(angle);

        // Обновляем карту этим лучом!
        updateMapWithLaser(robot_x_, robot_y_, hit_x, hit_y);
    }

    // После обработки всех лучей — публикуем обновлённую карту
    publishMap();
}

Публикация карты в /map

Чтобы RViz показал карту, нужно опубликовать её в топик /map в формате OccupancyGrid:

void publishMap() {
    auto grid = nav_msgs::msg::OccupancyGrid();

    // Заголовок
    grid.header.stamp = this->get_clock()->now();
    grid.header.frame_id = "odom";

    // Параметры сетки
    grid.info.resolution = RESOLUTION;       // 0.05 м на клетку
    grid.info.width = MAP_SIZE;              // 200 клеток
    grid.info.height = MAP_SIZE;
    grid.info.origin.position.x = ORIGIN_X;  // -5.0
    grid.info.origin.position.y = ORIGIN_Y;

    // Данные карты
    grid.data = map_data_;

    map_pub_->publish(grid);
}

После этого в RViz добавь отображение /map (Add → By topic → /map → Map) — увидишь, как карта появляется по мере движения робота.

Важный момент: неизвестное = проходимо

В нашем проекте неизвестные клетки (-1) считаются проходимыми. Почему? Потому что робот должен исследовать карту — ехать в неизведанные области. Если бы неизвестное = стена, робот никогда не поехал бы в туман войны.

Формально, функция isFree проверяет:

bool isFree(int x, int y) {
    if (x < 0 || x >= MAP_SIZE || y < 0 || y >= MAP_SIZE) return false;
    int val = map_data_[y * MAP_SIZE + x];
    return val == 0 || val == -1;  // свободно ИЛИ неизвестно
}

Это ключевая деталь из задания преподавателя. Без неё A* не сможет проложить путь через неисследованные зоны.

Поток данных: от луча до карты

Выбор параметров карты

ПараметрЗначениеПочему
RESOLUTION 0.05 м (5 см) Достаточно точно для навигации. Меньше — больше памяти и медленнее A*
MAP_SIZE 200 клеток 200 × 0.05 = 10 метров на сторону. Для учебного мира хватит
ORIGIN_X/Y -5.0 м Карта покрывает от -5 до +5 метров. Робот стартует примерно в центре

Итоги шага

Теперь ты понимаешь:

  • OccupancyGrid — карта из клеток: 0 = свободно, 100 = стена, -1 = неизвестно.
  • Ray tracing (Брезенхэм) — проводим линию от робота до точки попадания луча. Все клетки на пути = свободны, последняя = стена.
  • updateMapWithLaser — наша функция, которая вызывается для каждого луча 360 раз за скан.
  • Неизвестное = проходимо — иначе робот не сможет исследовать.

В следующем шаге используем эту карту, чтобы найти путь через A*.
