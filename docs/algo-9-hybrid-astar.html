Hybrid A*

Алгоритм №9 — A* с учётом физики: руль, скорость, кинематика

Зачем это нужно

Представь, что ты вызвал такси. Навигатор показывает маршрут — набор поворотов по улицам. Теперь представь, что навигатор говорит: «поверни на 90° на месте, потом шаг вбок». Водитель так не сможет — у машины есть руль с ограниченным углом и минимальный радиус разворота. Hybrid A* — это навигатор, который знает, что ты за рулём, а не на своих двоих.

Все алгоритмы до этого (A*, D* Lite, JPS, LPA*) считают, что робот — точка, которая шагает по клеткам. Hybrid A* — первый алгоритм в нашем списке, который учитывает физику робота: угол поворота $\theta$, минимальный радиус $R_{min}$, длину колёсной базы $L$.

Состояние — не $(x, y)$, а $(x, y, \theta)$. Переходы — не шаги по сетке, а реальные дуги, по которым робот может проехать.

Модель велосипеда (bicycle model)

Кинематику любого колёсного робота (TurtleBot, автомобиль, погрузчик) можно упростить до двухколёсной модели: переднее колесо рулит, заднее катится.

$$x' = x + \Delta s \cos\theta, \quad y' = y + \Delta s \sin\theta, \quad \theta' = \theta + \frac{\Delta s}{L} \tan\delta$$

$\Delta s$ — длина шага, $L$ — колёсная база, $\delta$ — угол руля (от $-\delta_{max}$ до $+\delta_{max}$), $R_{min} = L / \tan\delta_{max}$ — минимальный радиус поворота.

Неголономность: робот не может двигаться вбок. Чтобы сместиться в сторону — нужна дуга. Обычный A* этого не знает и рисует невозможные ступеньки.

Пространство состояний: 2D → 3D

Обычный A*

Состояние: $(x, y) \in \mathbb{Z}^2$

8 соседей, шаг = 1 клетка

Разворот на месте — бесплатно

Пешеход: куда хочу, туда иду

Hybrid A*

Состояние: $(x, y, \theta) \in \mathbb{R}^2 \times [0, 2\pi)$

3–7 маневров (углы руля)

Минимальный радиус поворота $R_{min}$

Водитель: кручу руль, еду дугами

Сетка нужна только для дискретизации: в каждой ячейке $(i, j, k)$ хранится лучшее непрерывное состояние. $k$ — дискретный угол ($\theta$ делим на $N_\theta$ секторов, обычно 36–72).

Маневры: что умеет робот

На каждом шаге робот проезжает расстояние $\Delta s$ и крутит руль на один из фиксированных углов. Это и есть его «соседи» — только не клетки, а дуги.

МаневрУгол руля $\delta$Что происходит
Прямо$0$Едет прямо на $\Delta s$
Лево макс.$+\delta_{max}$Крутая дуга влево (радиус $R_{min}$)
Право макс.$-\delta_{max}$Крутая дуга вправо (радиус $R_{min}$)
Лево плавно$+\delta_{max}/2$Плавная дуга влево (радиус $2R_{min}$)
Право плавно$-\delta_{max}/2$Плавная дуга вправо (радиус $2R_{min}$)

Обычно 3–5 маневров. Больше → плавнее путь, но дольше поиск.

Как работает

По сути это тот же A* — приоритетная очередь, $f = g + h$, visited-массив. Но с тремя ключевыми отличиями:

Отличие 1: 3D-ячейки вместо 2D

В обычном A* ячейка — $(x, y)$. В Hybrid A* — $(x, y, \theta)$. Пространство $\theta$ делим на $N_\theta$ секторов (обычно 72, т.е. шаг 5°). Это значит, что робот в одной и той же клетке, но с разным углом — это разные состояния. Стоишь на перекрёстке лицом на север и лицом на юг — два разных мира для машины с рулём.

Отличие 2: «соседи» — это дуги, а не клетки

Вместо 8 соседних клеток мы применяем 3–5 маневров (углов руля) и получаем 3–5 дуг. Каждая дуга заканчивается в непрерывной точке $(x', y', \theta')$, которую мы потом «округляем» в 3D-ячейку. Если в этой ячейке уже есть вариант с меньшим $g$ — новый отбрасываем.

Отличие 3: Analytic Expansion

Каждые N итераций алгоритм пробует аналитическую кривую (Dubins или Reeds-Shepp) напрямую от текущего состояния к цели. Если кривая не проходит через стены — путь найден, поиск завершён. Это превращает долгий «ползущий» финал в мгновенный прыжок к цели.

Почему «Hybrid»? Поиск идёт по дискретной 3D-сетке (как A*), но внутри каждой ячейки хранится непрерывное состояние. Гибрид дискретного графового поиска и непрерывной кинематики. Отсюда название.

Алгоритм по шагам

1
Кладём стартовое $(x_0, y_0, \theta_0)$ в очередь с приоритетом $f = h(\text{start})$.
2
Берём из очереди состояние с минимальным $f$.
3
Пробуем analytic expansion к цели. Если проходит — готово.
4
Применяем каждый маневр → получаем новые дуги. Каждую проверяем на коллизию с учётом footprint робота.
5
Для каждой свободной дуги: дискретизируем конечную точку в 3D-ячейку, сравниваем $g$ с тем, что уже в visited. Если лучше — обновляем и кладём в очередь.
6
Повторяем с шага 2.

Двойная эвристика

Hybrid A* уникален тем, что использует две разных эвристики одновременно — и берёт максимум. Каждая «знает» то, чего не знает другая:

$h_1$: Кинематика без стен

Длина Dubins/Reeds-Shepp кривой до цели, игнорируя препятствия.

Знает про руль и радиус поворота, но не видит стены.

$h_1 = \text{Dubins}(\text{state}, \text{goal})$

$h_2$: Стены без кинематики

Обычный 2D A*/Dijkstra от позиции до цели, игнорируя угол $\theta$.

Видит стены и обходит их, но не знает про руль.

$h_2 = \text{2D\_Grid}(x, y, \text{goal})$
$$h(s) = \max\big(h_1(s),\; h_2(s)\big)$$

Максимум двух допустимых эвристик — тоже допустимая эвристика, но более точная. Это отсекает больше бесполезных состояний.

Визуальный пример

Одна и та же карта, одни и те же препятствия — но два разных алгоритма рисуют принципиально разные пути:

A* — ступенчатый путь

Резкие повороты на 90°. Робот так не проедет.

Hybrid A* — плавные дуги

Плавная кривая с учётом $R_{min}$. Робот проедет сразу.

Интерактивная анимация

Смотри, как Hybrid A* расширяет дуги шаг за шагом. Серые пунктирные — отброшенные маневры (коллизия). Оранжевые — принятые. Зелёная — финальный путь через analytic expansion.

Реализация на Python

Полная реализация Hybrid A*. Ключевое отличие от обычного A*: состояние = (x, y, θ), кинематическая модель (bicycle), дискретизация по 3D-клеткам.

import math
from heapq import heappush, heappop
from dataclasses import dataclass, field

N_THETA: int = 72                  # 5° шаг угла
ANGLE_RES: float = 2 * math.pi / N_THETA
L: float = 0.3                    # колёсная база [м]
DS: float = 0.1                   # шаг [м]
DELTA_MAX: float = 0.5            # макс. угол руля [рад]
STEERS: list[float] = [
    -DELTA_MAX, -DELTA_MAX/2, 0.0, DELTA_MAX/2, DELTA_MAX
]


@dataclass
class State3D:
    x: float
    y: float
    theta: float
    g: float = 0.0
    f: float = 0.0
    parent_idx: int = -1

    def disc(self, res: float) -> tuple[int, int, int]:
        """Дискретизация (x,y,θ) → (i, j, k_θ)."""
        ix: int = int(self.x / res)
        iy: int = int(self.y / res)
        ik: int = int(self.theta / ANGLE_RES) % N_THETA
        return (ix, iy, ik)


def simulate(s: State3D, delta: float) -> State3D:
    """Один шаг кинематической модели (bicycle model)."""
    nx: float = s.x + DS * math.cos(s.theta)
    ny: float = s.y + DS * math.sin(s.theta)
    nt: float = s.theta + (DS / L) * math.tan(delta)
    nt = nt % (2 * math.pi)              # нормализация [0, 2π)
    return State3D(x=nx, y=ny, theta=nt)


def collision_free(
    s: State3D,
    grid: list[list[bool]],
    res: float
) -> bool:
    """Проверка: клетка, в которую попадает (x,y), свободна?"""
    ix: int = int(s.x / res)
    iy: int = int(s.y / res)
    if ix < 0 or iy < 0 or iy >= len(grid) or ix >= len(grid[0]):
        return False
    return not grid[iy][ix]


def heuristic_2d(s: State3D, goal: State3D) -> float:
    """Евклидово расстояние (нижняя граница)."""
    return math.hypot(s.x - goal.x, s.y - goal.y)


def hybrid_astar(
    grid: list[list[bool]],
    res: float,
    start: State3D,
    goal: State3D,
    max_iter: int = 50000
) -> list[State3D] | None:
    """Hybrid A* с bicycle model. Возвращает путь или None."""

    start.g = 0.0
    start.f = heuristic_2d(start, goal)
    nodes: list[State3D] = [start]
    visited: dict[tuple, int] = {start.disc(res): 0}

    counter: int = 0
    open_heap: list = [(start.f, counter, 0)]
    goal_thresh: float = res * 1.5     # порог достижения цели

    for _ in range(max_iter):
        if not open_heap:
            return None

        _, _, idx = heappop(open_heap)
        cur: State3D = nodes[idx]

        # Достигли цели?
        if math.hypot(cur.x-goal.x, cur.y-goal.y) < goal_thresh:
            path: list[State3D] = []
            i: int = idx
            while i != -1:
                path.append(nodes[i])
                i = nodes[i].parent_idx
            path.reverse()
            return path

        # Expand: 5 углов руля
        for delta in STEERS:
            nxt: State3D = simulate(cur, delta)

            if not collision_free(nxt, grid, res):
                continue

            disc = nxt.disc(res)
            nxt.g = cur.g + DS
            nxt.f = nxt.g + heuristic_2d(nxt, goal)
            nxt.parent_idx = idx

            if disc in visited:
                old_idx: int = visited[disc]
                if nodes[old_idx].g <= nxt.g:
                    continue                  # уже есть лучший

            new_idx: int = len(nodes)
            nodes.append(nxt)
            visited[disc] = new_idx
            counter += 1
            heappush(open_heap, (nxt.f, counter, new_idx))

    return None


# === Пример ===
# grid[y][x] = True если стена. res = 0.1 м/клетка.
# start = State3D(0.5, 0.5, 0.0)
# goal  = State3D(4.0, 4.0, math.pi/2)
# path = hybrid_astar(grid, 0.1, start, goal)

Отличия от обычного A*:

  • State3D(x, y, θ) — непрерывные координаты + угол, а не дискретные клетки
  • simulate() — bicycle model вместо 8 соседей. 5 углов руля = 5 манёвров
  • disc() — дискретизация 3D→ячейка для visited-массива (без неё — бесконечные состояния)
  • goal_thresh — достижение «рядом с целью» вместо точного совпадения

Ключевые компоненты: 3D-состояние, bicycle model, analytic expansion через OMPL.

#include <nav_msgs/msg/occupancy_grid.hpp>
#include <ompl/base/spaces/ReedsSheppStateSpace.h>
#include <queue>
#include <cmath>

constexpr int N_THETA = 72;            // 5° шаг угла
constexpr double ANGLE_RES = 2*M_PI / N_THETA;
constexpr double L = 0.3;              // колёсная база [м]
constexpr double DS = 0.1;             // шаг [м]
constexpr double DELTA_MAX = 0.5;      // макс. угол руля [рад]
constexpr double R_MIN = L / tan(DELTA_MAX);

struct State3D {
    double x, y, theta;
    double g = 0, f = 0;
    int parent_idx = -1;

    // Дискретизация для visited-массива
    int ix(double res) const { return (int)(x / res); }
    int iy(double res) const { return (int)(y / res); }
    int itheta() const {
        int k = (int)(theta / ANGLE_RES);
        return ((k % N_THETA) + N_THETA) % N_THETA;
    }
};

// Кинематическая модель (bicycle)
State3D simulate(const State3D& s, double delta) {
    State3D n;
    n.x = s.x + DS * cos(s.theta);
    n.y = s.y + DS * sin(s.theta);
    n.theta = s.theta + (DS / L) * tan(delta);
    // Нормализуем угол в [0, 2π)
    n.theta = fmod(n.theta, 2*M_PI);
    if (n.theta < 0) n.theta += 2*M_PI;
    return n;
}

Какой планировщик выбрать

A* / JPS

Робот omnidirectional (может ехать в любую сторону). Дроны, mecanum-колёса, дифф-привод без ограничений.
Точка на сетке, быстро, оптимально

Nav2: SmacPlanner2D

Hybrid A*

Робот с рулём — автомобиль, Ackermann, вилочный погрузчик. Есть $R_{min}$, нужен сразу проезжаемый путь.
Дуги в 3D, учёт кинематики, ~оптимально

Nav2: SmacPlannerHybrid

Lattice Planner

Сложная кинематика, нужны предрассчитанные маневры (parallel parking, 3-point turn). Индустриальные AGV.
Таблица маневров, дорогой precompute

Nav2: SmacPlannerLattice

Когда использовать

Простое правило: если твой робот не умеет разворачиваться на месте — тебе нужен Hybrid A*. Если умеет (omnidirectional, diff-drive) — обычного A* хватит.

РоботПланировщикПочему
Автомобиль, вилочный погрузчик Hybrid A* Есть руль, минимальный радиус — путь должен быть сразу проезжаемый
TurtleBot, diff-drive A* / JPS Может поворачиваться на месте — кинематика не ограничивает маршрут
Mecanum, omni-колёса A* / JPS Едет в любую сторону — обычная 2D-сетка идеальна
Промышленный AGV с парковкой Lattice Нужны предрассчитанные манёвры (3-point turn, парковка задним ходом)
Дрон / манипулятор RRT / PRM 6+ степеней свободы — сетка не подходит, нужен sampling

Цена за реализм

Hybrid A* работает медленнее обычного A*, потому что пространство состояний больше в $N_\theta$ раз (обычно 72×). На практике analytic expansion компенсирует это — вблизи цели алгоритм «прыгает» аналитической кривой вместо того, чтобы ползти по ячейкам. На карте 200×200 с $N_\theta = 72$ планирование занимает десятки миллисекунд — вполне достаточно для реального времени.
